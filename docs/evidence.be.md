# Што паказана, а што не { #what-has-and-has-not-been-shown }

У гэтым раздзеле сказана, на чым грунтуюцца сцвярджэнні праекта. Большая
частка звестак атрымана на імітаваных сканах, а не на паперы.

## Імітаваныя сканы { #simulated-scans }

Аўтаматычныя тэсты чытаюць згенераваныя выявы з размыццём, шумам і
паваротам. Імітаванае размыццё падабрана па трох рэальных сканах адной
надрукаванай старонкі пры 300 dpi, зробленых на адным прынтары і адным
сканеры з аўтападачай аркушаў.

- Пры такім размыцці стандартныя кропкі пры 300 dpi звычайным метадам
  чытання не раскадаваліся.
- Сярэднія кропкі са стандартнай абаронай прайшлі праверку пры 300 dpi і пры
  200 dpi.
- Вялікія, буйныя і вельмі буйныя кропкі прайшлі праверку пры 200 dpi без
  памылак.
- Дакумент з 12 старонак прайшоў праверку, калі адну старонку
  наўмысна не далі праграме.

## Павольны метад чытання { #the-slower-reader }

[Павольны метад чытання](slower-reader.md) паказаны на адным рэальным
дакуменце і адным імітаваным.

**Рэальны.** Дакумент уладальніка праекта з шасці старонак A4, стандартныя
кропкі, высокая абарона, адсканаваны прыкладна пры 290 dpi, хоць
рэкамендуецца 600 dpi. Звычайны метад не апазнаў ніводнай старонкі. З
павольным метадам файл быў адноўлены і прайшоў праверку па адбітку:
759 879 байтаў, з якіх 41 495 байтаў выправіла абарона дакумента, а
найгоршы блок выкарыстаў 40 са свайго рэсурсу 64. Гэта адзін дакумент,
адзін прынтар, адзін сканер і адна раздзяляльнасць. Сканаў у рэпазіторыі
няма.

**Імітаваны** (`tests/unit/test_coarse_claim.py`). Дакумент з дзвюх
старонак таго ж віду, адсканаваны пры 290 і пры 300 dpi з размыццём 1,8
кропкі прынтара. Пры 290 dpi звычайны метад не апазнае ніводнай старонкі;
пры 300 dpi ён чытае надпіс кожнай старонкі, але не загаловак. У абодвух
выпадках з павольным метадам файл праходзіць праверку. Пры размыцці
сімулятара па змаўчанні (1,0) звычайны метад сам чытае такую старонку пры
300 dpi.

Сімулятар мякчэйшы за сканер уладальніка: пры 290 dpi у імітацыі павольны
метад нічога не выпраўляў, тады як рэальнаму дакументу спатрэбілася
выправіць 41 495 байтаў.

Рэсурс стандартнай абароны — 32, менш за 40, якія спатрэбіліся найгоршаму
блоку рэальнага дакумента. Таму чакаецца, што дакумент са стандартнай
абаронай, адсканаваны так, не будзе адноўлены. Старыя старонкі ў стылі 0.2
павольны метад не ахоплівае.

## Што не паказана { #what-is-not-shown }

- Ніводнага рэальнага скана старонкі з большымі кропкамі яшчэ не
  прачытана.
- Чытанне надпісаў і раскадаванне маюць аўтаматычныя тэсты толькі на
  сінтэтычных сканах, а не на рэальна надрукаваных і адсканаваных старонках.
  Гэта датычыць кожнай раздрукоўкі з большымі кропкамі або з абаронай.
- Сканеры з аўтападачай аркушаў не выпрабаваны, калі не лічыць таго, што
  праграма знайшла сетку кропак на трох рэальных сканах.
- Тры рэальныя сканы адной раздрукоўкі пры 300 dpi далі прыкладна 286 dpi,
  гэта значыць, што раздрукоўка атрымалася прыкладна ў 95% натуральнай
  велічыні. Меншыя кропкі цяжэй прачытаць, таму друкуйце ў натуральную
  велічыню (100%).
- Струменныя прынтары не выпрабоўваліся.

## Тыя самыя старонкі, што ў праграмы на C { #the-same-pages-as-the-c-program }

Старонкі кадавальніка на Python пабайтава супадаюць з вынікам першапачатковай
праграмы `optar` на C для A4, Letter і ўсіх пяці рэжымаў карэкцыі памылак.
Пазіцыі крыжоў і счытаныя біты дэкодара на Python пабітава супадаюць з
`unoptar` на C на сінтэтычных тэставых выявах. І тое, і другое звяраецца з
вынікамі праграм на C, якія былі запісаны адзін раз і захоўваюцца ў
`tests/vectors`.

Кожная старонка самаапазнавальнай раздрукоўкі застаецца звычайнай старонкай
optar: `unoptar` на C, сабраны з тым жа памерам сеткі, дакладна чытае яе
кропкі (запісана для буйных кропак на A4 і сярэдніх кропак на Letter). Ён
вяртае не файл, а даныя, у якіх файл абгорнуты дадатковымі звесткамі і
абаронай.
