# optar-ის ფორმატი { #the-optar-format }

ამ სპეციფიკაციის ნორმატიული ტექსტი ინგლისურია, [The optar format](https://mezinster.github.io/optar/format/): ფორმატს განსაზღვრავს ის და სატესტო ვექტორები საქაღალდეში `tests/vectors`. ეს თარგმანი საცნობაროა; თუ იგი ინგლისურ ტექსტს არ ემთხვევა, მოქმედებს ინგლისური ტექსტი.

optar ფაილს ქაღალდზე ინახავს შავი და თეთრი წერტილებისგან შედგენილი
გვერდების სახით. ეს სპეციფიკაცია განსაზღვრავს, რა არის გვერდი და რა არის
დოკუმენტი (გვერდების ნაკრები, რომელიც ერთ ფაილს ატარებს), რათა შესაძლებელი
იყოს დაიწეროს კოდერი, რომლის გვერდებსაც ეს პროექტი წაიკითხავს, და დეკოდერი,
რომელიც ამ პროექტის გვერდებს წაიკითხავს.

სპეციფიკაცია რვა ნაწილისგან შედგება:

1. ტერმინები და შეთანხმებები
2. გვერდი (ვერსია 0)
3. დოკუმენტის ჭდე (0.2.0-ის ამონაბეჭდები)
4. თვითამოცნობადი დოკუმენტები (ვერსია 1)
5. ბეჭდვა
6. რა უნდა გააკეთოს წამკითხავმა პროგრამამ
7. საცნობარო დეკოდერი (ინფორმაციული)
8. ისტორია

ნაწილები 1-დან 6-მდე ნორმატიულია. სიტყვა „უნდა“ (must) გამოიყენება მხოლოდ
იმის სათქმელად, თუ რა არის გვერდი ან დოკუმენტი, ხოლო მე-6 ნაწილში — იმის
სათქმელად, თუ რას აკეთებს წამკითხავი პროგრამა წაკითხულით. როგორ პოულობს
წამკითხავი პროგრამა გვერდს სკანზე და როგორ იღებს მისგან ნიმუშებს, ფორმატის
ნაწილი არ არის; მე-7 ნაწილი აღწერს, როგორ აკეთებს ამას ეს პროექტი.

ფორმატს აფიქსირებს სატესტო ვექტორები საქაღალდეში `tests/vectors`. ყოველი
ნორმატიული განყოფილება მთავრდება სტრიქონით „ვექტორები:“, რომელიც ასახელებს
მის მაფიქსირებელ ფაილებს; როგორ იკითხება თითოეული ფაილი, ნათქვამია ფაილში
`tests/vectors/README.md`. ცხრილებს, რომლებსაც წინ უძღვის `spec-table`
კომენტარი, და `example` ნიშნით მონიშნულ ბლოკებს კოდს ადარებს
`tests/unit/test_spec.py`.

## 1. ტერმინები და შეთანხმებები { #1-terms-and-conventions }

### 1.1 რიცხვები, ბიტები და ბაიტები { #11-numbers-bits-and-bytes }

- ყველა მთელი რიცხვი ათობით სისტემაშია ჩაწერილი, თუ მას `0x` პრეფიქსი არ აქვს.
- `a // b` არის ქვემოთ დამრგვალებული გაყოფა, `a mod b` — მისი ნაშთი,
  `ceil(a / b)` — ზემოთ დამრგვალებული გაყოფა. სამივე გამოიყენება მხოლოდ
  არაუარყოფით მთელ რიცხვებზე.
- რაოდენობები და ინდექსები 0-დან იწყება, გარდა გვერდების ნომრებისა და 2.5
  განყოფილების დოდეკაედრის წახნაგებისა, რომლებიც 1-დან იწყება.
- **ბიტური სტრიქონი** იკითხება უფროსი ბიტიდან: ბაიტური სტრიქონის ბიტი `n`
  არის ბაიტის `n // 8` ბიტი `7 - (n mod 8)`, სადაც ბაიტის ბიტი 7 მისი უფროსი
  ბიტია. ბიტური სტრიქონიდან აღებული `w` ბიტიანი სიტყვის უფროსი ბიტი
  სტრიქონის პირველი ბიტია.
- თავსართის (განყოფილება 4.2) მრავალბაიტიანი მთელი რიცხვები big-endian
  რიგითაა ჩაწერილი: უფროსი ბაიტი პირველია.
- SHA-256 და CRC-32 ჩვეულებრივი ფუნქციებია. CRC-32 იგივეა, რაც zlib-ში,
  PNG-სა და Ethernet-ში: არეკლილი მრავალწევრი `0xEDB88320`, საწყისი
  მნიშვნელობა და საბოლოო XOR `0xFFFFFFFF`.

### 1.2 პიქსელები და ფერები { #12-pixels-and-colours }

- **გვერდი** არის **გვერდის პიქსელებისგან** შედგენილი მართკუთხა გამოსახულება.
  გვერდის ყოველი პიქსელი ან შავია, ან თეთრი.
- შავი მონაცემთა პიქსელი არის ბიტი 1; თეთრი მონაცემთა პიქსელი — ბიტი 0.
- 8-ბიტიან ნაცრისფერ გამოსახულების ფაილებში შავი პიქსელის მნიშვნელობაა 0,
  თეთრისა — 255. ეს სპეციფიკაცია გამოსახულების სხვა კოდირებას არ იყენებს.
- გვერდის კოორდინატებია `(x, y)`: `x` ითვლის სვეტებს მარცხენა კიდიდან, `y` —
  სტრიქონებს ზედა კიდიდან, ორივე 0-დან. გვერდი იბეჭდება და იკითხება სწორ
  მდებარეობაში, წარწერის ზოლით (განყოფილება 2.8) ქვემოთ.
- **მონაცემთა არის კოორდინატები** `(u, v)` ჩარჩოს (განყოფილება 2.2) არ
  მოიცავს: `u = x - border`, `v = y - border`.

### 1.3 ერთეულები { #13-units }

- **პუნქტი** (pt) არის 1/72 დუიმი.
- **პრინტერის წერტილი** არის 1/600 დუიმი: იმ 600 dpi პრინტერის მოწყობილობის
  ერთი წერტილი, რომლისთვისაც განლაგებებია შექმნილი.
- **მონაცემთა წერტილი** არის გვერდის ერთი პიქსელი დაბეჭდილი სახით. იგი
  პრინტერის წერტილების მთელი რაოდენობისგან შედგენილი კვადრატია (განყოფილება
  5.1). **სტანდარტული** მონაცემთა წერტილის სიგანე პრინტერის 3 წერტილია,
  1/200 დუიმი.

### 1.4 დოკუმენტის სახეები { #14-kinds-of-document }

**ნაკადი** არის ბაიტური სტრიქონი, რომელსაც დოკუმენტის გვერდები თავიანთ
მონაცემთა პიქსელებში ატარებს. არსებობს დოკუმენტის სამი სახე; სამივე ერთი და
იგივე 0 ვერსიის გვერდებისგან შედგება (ნაწილი 2).

| სახე | ვინ წერს | ნაკადი არის | წარწერა ატარებს |
|---|---|---|---|
| მარტივი | C-ზე დაწერილი პროგრამა, optar 0.1.0, `--no-tag` | ფაილი | მხოლოდ თავისუფალ ტექსტს |
| ჭდიანი | optar 0.2.0, ხოლო უფრო ახალი ვერსიები — თავიანთი „თავსებადი“ ამონაბეჭდის სახით | ფაილი | ჭდეს (ნაწილი 3) |
| თვითამოცნობადი | optar 0.3.0 და უფრო ახალი | კონტეინერი (ნაწილი 4) | მხოლოდ თავისუფალ ტექსტს |

## 2. გვერდი (ვერსია 0) { #2-the-page-version-0 }

### 2.1 გვერდის ფორმატი და ფორმატის სტრიქონი { #21-the-page-format-and-the-format-string }

**გვერდის ფორმატი** არის რვა არაუარყოფითი მთელი რიცხვი:

| ველი | სახელი | აზრი | უნდა იყოს |
|---|---|---|---|
| 1 | `version` | გვერდის ფორმატის ვერსია | 0 |
| 2 | `xcrosses` | ჯვრები სტრიქონში | სულ მცირე 2 |
| 3 | `ycrosses` | ჯვრები სვეტში | სულ მცირე 2 |
| 4 | `cpitch` | მანძილი ჯვრების სათავეებს შორის | `2 * chalf`-ზე მეტი |
| 5 | `chalf` | ჯვრის მხარის ნახევარი | სულ მცირე 1 |
| 6 | `fec_order` | გვერდის კოდი | 1-დან 5-მდე |
| 7 | `border` | ჩარჩოს სისქე | სულ მცირე 1 |
| 8 | `text_height` | წარწერის ზოლის სტრიქონები | `LABEL_HEIGHT` |

**ფორმატის სტრიქონი** არის რვავე ველი ამ რიგით, ათობით ჩანაწერში, წინა
ნულების გარეშე, `-` ნიშნით შეერთებული. ყოველი გვერდი თავის ფორმატის
სტრიქონს თავის წარწერაში ბეჭდავს (განყოფილება 2.8). ამ პროექტის მიერ
დაბეჭდილი გვერდები ერთმანეთისგან მხოლოდ `xcrosses` და `ycrosses` ველებით
განსხვავდება; დანარჩენ ველებს 1.5 განყოფილების მნიშვნელობები აქვს. ათი
გვერდის ფორმატი, რომლებსაც იგი ბეჭდავს, ჩამოთვლილია 5.2 განყოფილებაში. სხვა
მნიშვნელობებიც მართებულ გვერდებს იძლევა და ასეთი გვერდები იკითხება, როცა
წამკითხავ პროგრამას ფორმატის სტრიქონი მიეცემა.

ქვემოთ ყველა ზომა გვერდის პიქსელებშია.

    data_width  = cpitch * (xcrosses - 1) + 2 * chalf
    data_height = cpitch * (ycrosses - 1) + 2 * chalf
    width       = 2 * border + data_width
    height      = 2 * border + data_height + text_height

A4 გვერდს.

### 2.2 გვერდის ნაწილები { #22-the-parts-of-a-page }

გვერდი არის `width` სვეტი `height` სტრიქონზე. ზემოდან ქვემოთ:

| სტრიქონები `y` | შიგთავსი |
|---|---|
| `0`-დან `border - 1`-მდე | ჩარჩო: შავი |

| `border + data_height`-დან `border + data_height + text_height - 1`-მდე | **წარწერის ზოლი**: შავი მთელ სიგანეზე, წარწერით, რომელიც თეთრადაა დახატული სვეტებში `border`-დან `border + data_width - 1`-მდე (განყოფილება 2.8) |

მონაცემთა პიქსელი (განყოფილება 2.4).

### 2.3 ჯვრები { #23-crosses }

მონაცემთა არე შეიცავს `xcrosses * ycrosses` **ჯვარს**, რომელთა მეშვეობითაც
წამკითხავი პროგრამა მონაცემთა პიქსელებს პოულობს. ჯვარი `(i, j)`,
`0 <= i < xcrosses`, `0 <= j < ycrosses`, არის `2 * chalf`-ზე `2 * chalf`
პიქსელის კვადრატი, რომლის ზედა მარცხენა პიქსელი, მისი **სათავე**, მდებარეობს
მონაცემთა არის კოორდინატებზე `(i * cpitch, j * cpitch)`. მისი ოთხი მეოთხედი,
თითოეული `chalf`-ზე `chalf` პიქსელი, ასეთია:

| მეოთხედი | ფერი |
|---|---|
| ზედა მარცხენა | შავი |
| ზედა მარჯვენა | თეთრი |
| ქვედა მარცხენა | თეთრი |
| ქვედა მარჯვენა | შავი |

პირველი ჯვარი მონაცემთა არის ზედა მარცხენა კუთხეს ეხება, ბოლო კი — მის ქვედა
მარჯვენა კუთხეს. მონაცემთა არის პიქსელი `(u, v)` ჯვრის ნაწილია ზუსტად მაშინ,
როცა `u mod cpitch < 2 * chalf` და `v mod cpitch < 2 * chalf`.

```example
a4_last_cross_x = 1538
a4_last_cross_y = 2210
```

ეს არის ბოლო ჯვრის სათავის გვერდის კოორდინატები `(x, y)`.

ვექტორები: `tests/vectors/c/encoder_pages.json`.

### 2.4 მონაცემთა პიქსელები და მათი რიგი { #24-data-pixels-and-their-order }

**მონაცემთა პიქსელები** არის მონაცემთა არის ის პიქსელები, რომლებიც ჯვრის
ნაწილი არ არის. ისინი 0-დან ინომრება კითხვის რიგით: სტრიქონ-სტრიქონ
ზემოდან, სტრიქონის შიგნით კი მარცხნიდან მარჯვნივ. მონაცემთა პიქსელის ნომერი
მისი **არხის პოზიციაა**; `total_bits` მონაცემთა პიქსელების რაოდენობაა.

მონაცემთა არის სტრიქონები `cpitch` პერიოდით მეორდება:

- **ვიწრო ზოლი** — `2 * chalf` სტრიქონი, რომლებიც ჯვრებზე გადის. თითოეული
  სტრიქონი შეიცავს `narrow_width` მონაცემთა პიქსელს, ჯვრებს შორის
  `xcrosses - 1` შუალედში, თითოეული `gap_width` პიქსელისა;
- **განიერი ზოლი** — `gap_width` სტრიქონი ჯვრების გარეშე. თითოეული სტრიქონი
  შეიცავს `data_width` მონაცემთა პიქსელს.

ბოლო პერიოდს მხოლოდ ვიწრო ზოლი აქვს.

    gap_width     = cpitch - 2 * chalf
    narrow_width  = gap_width * (xcrosses - 1)
    narrow_pixels = 2 * chalf * narrow_width
    wide_pixels   = gap_width * data_width
    rep_pixels    = narrow_pixels + wide_pixels
    total_bits    = rep_pixels * (ycrosses - 1) + narrow_pixels

`n` არხის პოზიციის მონაცემთა არის კოორდინატები `(u, v)` ასეთია:

    rep = n // rep_pixels
    s   = n mod rep_pixels
    if s < narrow_pixels:                      (narrow strip)
        row = s // narrow_width
        r   = s mod narrow_width
        u   = 2 * chalf + (r // gap_width) * cpitch + r mod gap_width
        v   = rep * cpitch + row
    else:                                      (wide strip)
        s   = s - narrow_pixels
        u   = s mod data_width
        v   = rep * cpitch + 2 * chalf + s // data_width

გვერდის კოორდინატებია `(u + border, v + border)`.

```example
a4_narrow_width = 1152
a4_narrow_pixels = 6912
a4_wide_pixels = 27756
a4_rep_pixels = 34668
a4_total_bits = 3196368
a4_xy_of_0 = 6, 0
a4_xy_of_17 = 23, 0
a4_xy_of_18 = 30, 0
a4_xy_of_1152 = 6, 1
a4_xy_of_6912 = 0, 6
a4_xy_of_8454 = 0, 7
a4_xy_of_34668 = 6, 24
a4_xy_of_3196367 = 1535, 2213
```

`a4_xy_of_N` არის `N` არხის პოზიციის `u, v`.

ვექტორები: `tests/vectors/c/bit_placement.json`.

### 2.5 გვერდის კოდი { #25-the-page-code }

გვერდის მონაცემები იჭრება `small` ბიტიან **სიტყვებად**. ყოველი სიტყვა
კოდირდება `large` ბიტიან **სიმბოლოდ**, რომლის შესწორებაც შესაძლებელია, როცა
მისი რამდენიმე ბიტი არასწორად წაიკითხება. `fec_order` ირჩევს კოდს:

| `fec_order` | კოდი | `large` | `small` |
|---|---|---|---|
| 1 | გოლეის კოდი (24, 12) | 24 | 12 |
| 2-დან 5-მდე | გაფართოებული ჰემინგის კოდი | `2 ^ fec_order` | `large - 1 - fec_order` |

```example
code_bits_of_order_1 = 24, 12
code_bits_of_order_2 = 4, 1
code_bits_of_order_3 = 8, 4
code_bits_of_order_4 = 16, 11
code_bits_of_order_5 = 32, 26
```

სიმბოლო აქ იწერება როგორც `large` ბიტიანი მთელი რიცხვი; მისი **ბიტი `b`**,
იმ რიგით, რომლითაც ბიტები გვერდზე თავსდება, ითვლება უფროსი ბიტიდან: ბიტი 0
არის `2 ^ (large - 1)` მნიშვნელობის ბიტი.

#### გოლეის კოდი (24, 12) { #golay-24-12 }

12-ბიტიანი სიტყვის `d` სიმბოლოა `d * 4096 + p(d)`: სიტყვა ზედა 12 ბიტშია,
მის ქვემოთ — ლუწობის 12 ბიტი. ლუწობის ბიტები მიიღება დოდეკაედრიდან, რომლის
წახნაგებიც 1-დან 12-მდეა დანომრილი. წახნაგი `f` შეესაბამება `d`-ის
`2 ^ (f - 1)` მნიშვნელობის ბიტს. ყოველ წახნაგს ხუთი მეზობელი აქვს:

სულ მცირე 8 ბიტით განსხვავდება. ამიტომ 3-მდე არასწორი ბიტით წაკითხული
სიმბოლოდან 3 ბიტის ფარგლებში ზუსტად ერთი სიმბოლოა — ის, რომელიც დაიბეჭდა.
ვექტორების ფაილი აფიქსირებს ყველა 4096 სიმბოლოს.

#### გაფართოებული ჰემინგის კოდი (`fec_order` 2-დან 5-მდე) { #extended-hamming-fec_order-2-to-5 }

სიმბოლოს ბიტები დავნომროთ მათი მნიშვნელობით: პოზიცია `q` არის `2 ^ q`
მნიშვნელობის ბიტი, `0 <= q < large`.

1. სიტყვის ბიტები, უფროსიდან დაწყებული, თავსდება იმ პოზიციებზე, რომლებიც არც
   0-ია და არც ორის ხარისხი, `large - 1` პოზიციიდან კლებით.
2. `i`-სთვის 0-დან `fec_order - 1`-მდე პოზიცია `2 ^ i` ისე დგინდება, რომ იმ
   პოზიციებზე, რომელთა ნომერშიც ბიტი `i` დაყენებულია, 1-იანი ბიტების ლუწი
   რაოდენობა იყოს.
3. პოზიცია 0 ისე დგინდება, რომ მთელ სიმბოლოში 1-იანი ბიტების ლუწი რაოდენობა
   იყოს.

ასეთი სიმბოლოს შესწორება შესაძლებელია, როცა ერთი ბიტია არასწორი, ხოლო ორი
არასწორი ბიტი შეინიშნება. `fec_order` 2-ის დროს სიმბოლო არის სიტყვის
ერთადერთი ბიტი ოთხჯერ.

```example

hamming_3_of_1011 = 10101010
hamming_4_of_10000000001 = 1000000100011000
hamming_5_of_1 = 00000000000000000000000000001111
```

### 2.6 სიმბოლოები გვერდზე { #26-symbols-on-the-page }

გვერდი შეიცავს

    symbols   = total_bits // large
    used_bits = symbols * large
    net_bits  = symbols * small

`net_bits` არის მონაცემთა ბიტების რაოდენობა, რომელსაც გვერდი ატარებს.
სიმბოლოები ისეა გადანაწილებული, რომ მეზობელი პიქსელები სხვადასხვა სიმბოლოს
ეკუთვნის:

    bit b of symbol s is at channel position  s + b * symbols

`0 <= s < symbols`-ისა და `0 <= b < large`-ისთვის. ამრიგად, გოლეის კოდის
შემთხვევაში მონაცემთა პიქსელები ქმნის `symbols` პიქსელისგან შემდგარ 24
თანმიმდევრულ ჯგუფს, და ყოველ სიმბოლოს ყოველ ჯგუფში თითო პიქსელი აქვს,
ყველა ჯგუფში ერთსა და იმავე ადგილას.

მონაცემთა პიქსელები, რომლებიც `used_bits` და მეტ არხის პოზიციებზეა, არცერთ
სიმბოლოს არ ეკუთვნის და თეთრია.


`a4_medium_` პრეფიქსიანი სახელები ეხება ფორმატს `0-50-70-24-3-1-2-24`;
`hamming_N_net_bits` ეხება A4 ბადეს `fec_order` N-ით.

ვექტორები: `tests/vectors/c/bit_placement.json`, `tests/vectors/c/encoder_pages.json`.

### 2.7 ნაკადიდან გვერდებამდე { #27-from-a-stream-to-pages }

ვთქვათ, ნაკადი არის `nbytes` ბაიტი, წაკითხული როგორც ბიტური სტრიქონი
(განყოფილება 1.1).

    pages = ceil(8 * nbytes / net_bits)

გვერდი `p` (1-დან) ატარებს ნაკადის ბიტებს `(p - 1) * net_bits`-დან
`p * net_bits - 1`-მდე. გვერდის სიტყვა `s` არის `small` ბიტი, რომლებიც
გვერდის ბიტების `s * small` ბიტიდან იწყება, ხოლო სიმბოლო `s` მისი კოდია
(განყოფილება 2.5).

- ნაკადის დასასრულის შემდეგ მდებარე ბიტები 0-ია. ამრიგად, ბოლო სიტყვა,
  რომელიც ნაკადის ბიტებს შეიცავს, უმცროსი ბოლოდან 0 ბიტებით ივსება, და ბოლო
  გვერდის ყოველი მომდევნო სიტყვა 0-ია. სიტყვა 0-ის სიმბოლოა 0, ამიტომ ეს
  სიტყვები თეთრი პიქსელებით იბეჭდება.
- დოკუმენტს აქვს არაუმეტეს `MAX_PAGES` გვერდისა; უფრო გრძელი ნაკადის
  კოდირება შეუძლებელია.
- ცარიელი ნაკადი (`nbytes = 0`) იძლევა `pages = 0`. იგი იბეჭდება როგორც
  ერთი გვერდი, რომლის ყველა მონაცემთა პიქსელი თეთრია და რომლის წარწერაც
  გვერდის ნომრად 1-ს და გვერდების რაოდენობად 0-ს აჩვენებს (`1/0`).

გვერდების რიგით წაკითხვა და მათი `net_bits` ბიტის შეერთება იძლევა ნაკადს,
რომელსაც 0 ბიტები მოსდევს. გვერდი არ აღრიცხავს, სად მთავრდება ნაკადი:
მარტივი დოკუმენტი თავის ფაილს აბრუნებს ნულოვანი ბაიტებით შევსებულს მისი
ბოლო გვერდის ბოლომდე (იმ ბიტების გამოკლებით, რომლებიც ბაიტს ვერ ავსებს,
როცა `net_bits` 8-ის ჯერადი არ არის). ჭდეც (ნაწილი 3) და კონტეინერიც
(ნაწილი 4) ფაილის ზომას აღრიცხავს.

```example
a4_pages_for_0_bytes = 0
a4_pages_for_1_byte = 1
a4_pages_for_199773_bytes = 1
a4_pages_for_199774_bytes = 2
a4_words_for_1000_bytes = 667
```

1000 ბაიტიანი ნაკადი პირველი გვერდის 667 სიტყვას ავსებს; მათგან ბოლო
შეიცავს ნაკადის 8 ბიტს და ოთხ 0 ბიტს.

ვექტორები: `tests/vectors/c/encoder_pages.json`.

### 2.8 წარწერა { #28-the-label }

წარწერის ზოლი შეიცავს ტექსტის ერთ სტრიქონს — ადამიანებისთვის და, ჭდიან
დოკუმენტში, წამკითხავი პროგრამისთვის. იგი ყოველთვის ერთი და იმავე შრიფტით იხატება, რომელსაც
ქვემოთ აღწერილი შრიფტის ლენტი განსაზღვრავს.

**შრიფტის ლენტი** არის გამოსახულება `LABEL_HEIGHT` სტრიქონითა და 1500
სვეტით, რომლის ყოველი პიქსელი შავია ან თეთრი. სვეტები `0`-დან
`TEXT_WIDTH * GLYPH_CELLS - 1`-მდე შეიცავს `GLYPH_CELLS` ნიშნის უჯრას,
თითოეული `TEXT_WIDTH` სვეტისა: `c` კოდის მქონე ნიშნის უჯრა,
`32 <= c <= 126`, იწყება სვეტიდან `TEXT_WIDTH * (c - FIRST_CHAR)`. დანარჩენი
სვეტები ლოგოს შეიცავს. გლიფები და ლოგო თეთრია შავზე. ლენტი არის ამ პროექტის
ფაილი `src/optar/data/font.png` (მისი პიქსელი თეთრია, როცა მისი ნაცრისფრის
მნიშვნელობა 128 ან მეტია); ქვემოთ მოცემული მისი ჰეში არის მისი პიქსელების
SHA-256, ბაიტებად 0 (შავი) და 255 (თეთრი), სტრიქონ-სტრიქონ.

```example
strip_width = 1500
logo_width = 265
glyph_column_of_capital_a = 429
font_strip_sha256 = 481c0abd7884afb5ab6d958fbb95c0d6be97b0e2a7124f57e1abcd118d7d4bc4
```

**წარწერის სტრიქონი** გვერდისთვის `page` (სულ `total` გვერდიდან) თავისუფალი
ტექსტით `text` არის

    two spaces, the format string, a space, page, "/", total, a space, text

სადაც `page` და `total` ათობით ჩანაწერშია, წინა ნულების გარეშე. `total`-ის
შემდეგი ჰარი იწერება მაშინაც, როცა `text` ცარიელია. შემდეგ სტრიქონი
მოიჭრება მის პირველ `data_width // TEXT_WIDTH - 1` ნიშნამდე (Unicode-ის
კოდური პოზიციები).

**დახატვა.** ზოლის სიგანე `data_width` სვეტია, დანომრილი 0-დან გვერდის სვეტ
`border`-დან; ყველაფერი, რაც მასში არ არის დახატული, შავია.

1. თუ `logo_width <= data_width`, ლოგო კოპირდება ზოლის სვეტებში `0`-დან
   `logo_width - 1`-მდე.
2. კურსორი იწყება ზოლის სვეტ `logo_width`-დან, დაიხატა ლოგო თუ არა.
3. მოჭრილი სტრიქონის ყოველი ნიშნისთვის, რიგით: ნიშანი, რომლის კოდი 32-ზე
   ნაკლები ან 127-ზე მეტია, გამოიტოვება. სხვა შემთხვევაში, თუ კურსორს
   დამატებული `TEXT_WIDTH` არაუმეტეს `data_width`-ია, ლენტის `TEXT_WIDTH`
   სვეტი, რომლებიც `TEXT_WIDTH * (code - FIRST_CHAR)`-დან იწყება, კოპირდება
   ზოლში კურსორის ადგილას; ორივე შემთხვევაში კურსორი `TEXT_WIDTH`-ით
   გადაიწევს წინ.

სამი შედეგი, რომელიც კოდერმა უნდა გაიმეოროს, რათა იგივე გვერდები დაბეჭდოს:

- გვერდი აჩვენებს არაუმეტეს `(data_width - logo_width) // TEXT_WIDTH`
  ნიშნისა, რაც იმაზე ნაკლებია, რამდენ ნიშნამდეც სტრიქონი მოიჭრება; დანარჩენი
  არ იხატება.
- ნიშნები, რომელთა კოდიც 32-დან 127-მდე შუალედის გარეთაა, უჯრას არ იკავებს,
  მაგრამ ითვლება იმ სიგრძეში, რომელზეც სტრიქონი მოიჭრება.
- კოდი 127 უჯრას იკავებს და ლოგოს პირველ `TEXT_WIDTH` სვეტს ხატავს. ასეთი
  წარწერის უკან წაკითხვა შეუძლებელია.

```example
a4_label_line = "  0-65-93-24-3-1-2-24 3/7 backup.tar"
a4_label_characters = 117
a4_label_cells = 98
a4_xlarge_label_cells = 18
```

`a4_label_characters` არის სიგრძე, რომლამდეც სტრიქონი მოიჭრება, ხოლო
`a4_label_cells` — ნიშნების რაოდენობა, რომელსაც გვერდი აჩვენებს.
`0-22-31-24-3-1-2-24` ფორმატის გვერდი 18 ნიშანს აჩვენებს, ანუ ნაკლებს, ვიდრე
მის ფორმატის სტრიქონშია; 5.4 განყოფილებაში ნათქვამია, როგორ იბეჭდება ასეთი
გვერდების წარწერა.

ვექტორები: `tests/vectors/c/label.json`, `tests/vectors/c/encoder_pages.json`.

## 3. დოკუმენტის ჭდე (0.2.0-ის ამონაბეჭდები) { #3-the-document-tag-020-printouts }

მარტივი დოკუმენტი არ ამბობს, რა სიგრძისაა მისი ფაილი, რომელი გვერდები
ეკუთვნის ერთმანეთს და სწორად იქნა თუ არა ფაილი წაკითხული. **ჭდიანი
დოკუმენტი** ამას ყოველი წარწერის თავისუფალ ტექსტში ამბობს. მისი ნაკადი
თავად ფაილია, ამიტომ მის გვერდებს ის პროგრამებიც კითხულობს, რომლებმაც ჭდის
შესახებ არაფერი იციან.

### 3.1 ჭდე { #31-the-tag }

`size` ბაიტიანი ფაილისთვის:

- `SIZE` არის `size` ათობით ჩანაწერში, წინა ნულების გარეშე (`0` ცარიელი
  ფაილისთვის), არაუმეტეს `MAX_SIZE_DIGITS` ციფრისა;
- `FINGERPRINT` არის ფაილის SHA-256-ის პირველი `FINGERPRINT_DIGITS` ნიშანი,
  ჩაწერილი თექვსმეტობითი სახით, პატარა ასოებით;
- `CHECK` გვერდისთვის `page` (სულ `total`-დან) არის ASCII ტექსტის
  `SIZE:FINGERPRINT:page/total` თექვსმეტობითი, პატარა ასოებით ჩაწერილი
  SHA-256-ის პირველი `CHECK_DIGITS` ნიშანი, სადაც `page` და `total` ისეა
  ჩაწერილი, როგორც წარწერის სტრიქონში.

გვერდის ჭდე არის ტექსტი `[SIZE:FINGERPRINT:CHECK]`. გვერდის წარწერის
თავისუფალი ტექსტი არის ჭდე, ან ჭდე, ერთი ჰარი და სახელი. `SIZE` და
`FINGERPRINT` დოკუმენტის ყოველ გვერდზე ერთნაირია; `CHECK` გვერდიდან გვერდამდე
განსხვავდება.

ცარიელი ფაილი არის ერთი გვერდი წარწერით `1/0` (განყოფილება 2.7); მისი
საკონტროლო მნიშვნელობა გამოითვლება `page` 1-ითა და `total` 0-ით.

```example
tag_fingerprint_of_x = 2d711642
tag_check_input = "1:2d711642:1/1"
tag_check_of_x_page_1_of_1 = ca
tag_free_text = "[1:2d711642:ca] name.tar"
tag_of_empty_file = "[0:e3b0c442:e0]"
```

პირველი ოთხი სტრიქონი ეხება ერთბაიტიან ფაილს `x`, დაბეჭდილს სახელით
`name.tar`.

ვექტორები: `tests/vectors/py/tag.json`.

### 3.2 როდის არის ჭდე მართებული { #32-when-a-tag-is-valid }

წარწერის თავისუფალი ტექსტი **ჭდით იწყება**, როცა იგი იწყება `[`-ით, ზემოთ
აღწერილი ზომით, `:`-ით, ზუსტად 8 ნიშნით `0-9a-f`-დან, `:`-ით, ზუსტად 2
ნიშნით `0-9a-f`-დან და `]`-ით, და ჭდეს მოსდევს ჰარი ან ტექსტის დასასრული.

`F` გვერდის ფორმატში გვერდიდან `page` (სულ `total`-დან) წაკითხული ჭდე
**მართებულია**, როცა ორივე პირობა სრულდება:

- მისი საკონტროლო მნიშვნელობა უდრის წაკითხული ზომიდან, ანაბეჭდიდან,
  `page`-იდან და `total`-იდან გამოთვლილ საკონტროლო მნიშვნელობას;
- ზომა შეესაბამება გვერდების რაოდენობას: `size = 0` და `total = 0`, ან
  `size > 0`, `total > 0` და `(total - 1) * capacity < size <= total * capacity`,
  სადაც `capacity = net_bits // 8`, `F`-ის `net_bits`-ით.

ორ `standard` განლაგებაში (განყოფილება 5.2) `net_bits` 8-ის ჯერადია,
ამიტომ ზომა შეესაბამება ზუსტად იმ გვერდების რაოდენობას, რომელსაც მას 2.7
განყოფილება ანიჭებს. ამ პროექტის წამკითხავი პროგრამა გვერდებს ჭდით მხოლოდ
ამ ორ განლაგებაში ამოიცნობს.

ვექტორები: `tests/vectors/py/tag.json`.

## 4. თვითამოცნობადი დოკუმენტები (ვერსია 1) { #4-self-identifying-documents-version-1 }

**თვითამოცნობადი დოკუმენტი** ყოველი გვერდის მონაცემებში ატარებს თავსართს,
რომელიც ამბობს, რომელ დოკუმენტს ეკუთვნის გვერდი და რომელი გვერდია იგი, და
შეუძლია ატაროს ლუწობა, რომლითაც დაზიანებული გვერდები გამოსწორდება, ხოლო ის
გვერდები, რომლებიც აკლია, აღდგება. ფაილი, მისი სახელი და ლუწობა ჩალაგებულია
ნაკადში, **კონტეინერში**, და ეს ნაკადი იბეჭდება ჩვეულებრივ 0 ვერსიის
გვერდებად (ნაწილი 2). ვერსია 1 კონტეინერის ვერსიაა; გვერდის ფორმატი ვერსია
0-ს ინარჩუნებს.

### 4.1 ზომები { #41-sizes }

გვერდის ფორმატისთვის `F`, ლუწობის დონისთვის `parity` (განყოფილება 4.4) და
გვერდების რაოდენობისთვის `T`:

    page_bytes = net_bits // 8                         payload of one page
    page_body  = page_bytes - HEADER_COPIES * HEADER_SIZE
    k          = CODEWORD - parity                     data bytes of a codeword
    m(T)       = T * page_body // CODEWORD             codewords
    D(T)       = m(T) * k                              bytes of the data region

გვერდის **სასარგებლო დატვირთვა** არის მისი პირველი `page_bytes * 8`
მონაცემთა ბიტი, ბაიტებად. გვერდის **ტანი** არის მისი სასარგებლო დატვირთვა
თავსართის ასლების გარეშე (განყოფილება 4.3), `page_body` ბაიტი. **დოკუმენტის
ტანი** არის 1-დან `T`-მდე გვერდების შეერთებული ტანები, `T * page_body`
ბაიტი.

გვერდის ფორმატს კონტეინერის ტარება შეუძლია მხოლოდ მაშინ, თუ
`page_bytes // HEADER_COPIES >= HEADER_SIZE`.

```example
a4_page_bytes = 199773
a4_page_body = 199583
```

ვექტორები: `tests/vectors/py/container.json`.

### 4.2 თავსართი { #42-the-header }

თავსართი არის `HEADER_SIZE` ბაიტი:

<!-- spec-table: header-fields -->
| წანაცვლება | ზომა | ველი | ტიპი | შიგთავსი |
|---|---|---|---|---|
| 0 | 4 | `magic` | ბაიტები | `HEADER_MAGIC` |
| 4 | 1 | `version` | მთელი რიცხვი | `CONTAINER_VERSION` |
| 5 | 1 | `parity` | მთელი რიცხვი | ლუწობის ბაიტები კოდურ სიტყვაზე: 0, 32 ან 64 |
| 6 | 2 | `page` | მთელი რიცხვი | ამ გვერდის ნომერი, 1-დან |
| 8 | 2 | `total` | მთელი რიცხვი | გვერდები დოკუმენტში |
| 10 | 8 | `size` | მთელი რიცხვი | ფაილის ზომა ბაიტებში |
| 18 | 16 | `fingerprint` | ბაიტები | ფაილის SHA-256-ის პირველი `FINGERPRINT_SIZE` ბაიტი |
| 34 | 4 | `crc` | მთელი რიცხვი | 0-დან 33-მდე ბაიტების CRC-32 |

მთელი რიცხვები big-endian რიგითაა ჩაწერილი. ყველა ველი, გარდა `page`-ისა
(და მასთან ერთად `crc`-ისა), დოკუმენტის ყოველ გვერდზე ერთნაირია.


ლუწობით 64; ფაილის ანაბეჭდია ბაიტები `00`-დან `0f`-მდე.

### 4.3 გვერდის სასარგებლო დატვირთვა { #43-the-payload-of-a-page }

გვერდის თავსართის ასლი `c`, `0 <= c < HEADER_COPIES`, მდებარეობს სასარგებლო


### 4.5 რიდ-სოლომონის კოდი { #45-the-reed-solomon-code }

**კოდური სიტყვა** არის `CODEWORD` ბაიტი: `k` მონაცემთა ბაიტი, რომელსაც
`parity` ლუწობის ბაიტი მოსდევს.

- ბაიტები GF(256)-ის ელემენტებია ველის მრავალწევრით
  `x^8 + x^4 + x^3 + x^2 + 1` (`0x11D`): ბაიტი არის მრავალწევრი GF(2)-ზე,
  რომლის `x^7`-ის კოეფიციენტი მისი უფროსი ბიტია; შეკრება არის XOR, ხოლო
  გამრავლება — მრავალწევრთა გამრავლება ველის მრავალწევრის მოდულით.
- `alpha` არის ელემენტი `0x02`.
- წარმომქმნელი მრავალწევრია
  `g(x) = (x - alpha^0)(x - alpha^1) ... (x - alpha^(parity - 1))`.
- კოდური სიტყვის ბაიტი `i`, `0 <= i <= 254`, არის კოდური სიტყვის მრავალწევრის
  `c(x)` `x^(254 - i)`-ის კოეფიციენტი.
- მონაცემთა ბაიტები არის კოეფიციენტები `x^254`-დან `x^parity`-მდე. ლუწობის
  ბაიტები ისეა შერჩეული, რომ `g(x)` ყოფდეს `c(x)`-ს: ისინი არის მონაცემთა
  მრავალწევრის (`x^parity`-ზე დაბალი ნულოვანი კოეფიციენტებით) `g(x)`-ზე
  გაყოფის ნაშთი, `x^(parity - 1)`-ის კოეფიციენტიდან დაწყებული.

კოდური სიტყვის გამოსწორება შესაძლებელია, როცა `2 * e + f <= parity`, სადაც
`f` არის მისი იმ ბაიტების რაოდენობა, რომელთა შესახებაც ცნობილია, რომ ვერ
იკითხება (წაშლილი ბაიტები, erasures), ხოლო `e` — სხვა ბაიტების
რაოდენობა, რომლებიც არასწორია.

```example
gf_alpha_8 = 0x1d
gf_alpha_254 = 0x8e
rs_32_parity_of_one = 744034ae367e10c2a221219db0c5e10c3b37fde4942fb3b9188afd148e37ac58
rs_32_parity_of_counting = 41841183b11fdb537421939696cda70e1db5c86684af222564b89cc6069f172e
```

`rs_32_parity_of_one` არის ლუწობის ბაიტები (ლუწობა 32-ის დროს) იმ 223
მონაცემთა ბაიტისა, რომლებიც ყველა ნულია, გარდა ბოლო ბაიტისა, რომელიც 1-ია; ეს არის
`g(x)`-ის კოეფიციენტები `x^31`-დან `x^0`-მდე. `rs_32_parity_of_counting` არის
ლუწობის ბაიტები (ლუწობა 32-ის დროს) მონაცემთა ბაიტებისა 0, 1, 2, ..., 222.

ვექტორები: `tests/vectors/py/reed_solomon.json`.

### 4.6 მონაცემთა ზონა და გაფანტვა { #46-the-data-region-and-the-spread }

**მონაცემთა ზონა** არის `D(T)` ბაიტი:

| ბაიტები | შიგთავსი |
|---|---|
| `size` | ფაილი |
| 1 | `L`, სახელის სიგრძე ბაიტებში, 0-დან `NAME_MAX_BYTES`-მდე |
| `L` | ფაილის სახელი UTF-8-ში |
| დანარჩენი | შევსება (განყოფილება 4.7) |

სახელი, რომელიც UTF-8-ში `NAME_MAX_BYTES` ბაიტზე გრძელია, მოიჭრება
ნიშნების იმ უდიდეს მთელ რაოდენობამდე, რომელიც ეტევა. სახელს ანაბეჭდი არ
მოიცავს. სახელის ნიშანი, რომლის კოდირებაც UTF-8-ს არ შეუძლია (მარტოხელა
სუროგატული კოდური პოზიცია, U+D800-დან U+DFFF-მდე), ინახება როგორც `?`.

კოდური სიტყვის `j`, `0 <= j < m`, მონაცემთა ბაიტებია მონაცემთა ზონის ბაიტები
`j * k`-დან `j * k + k - 1`-მდე. ლუწობა 0-ის დროს კოდური სიტყვა არის მისი
255 მონაცემთა ბაიტი.

**გაფანტვა.** კოდური სიტყვის `j` ბაიტი `i` არის დოკუმენტის ტანის ბაიტი
პოზიციაზე

    i * m + (j + i * SPREAD_STEP) mod m

ამრიგად, ყოველი კოდური სიტყვის ბაიტი `i` მდებარეობს ტანის მონაკვეთში
`i * m`-დან `(i + 1) * m - 1`-მდე, ხოლო ერთი კოდური სიტყვის 255 ბაიტი — 255
სხვადასხვა მონაკვეთში, მთელ დოკუმენტზე გაფანტული: დაზიანება ერთ ადგილას
ყოველ კოდურ სიტყვას რამდენიმე ბაიტი უჯდება, ნაცვლად იმისა, რომ რამდენიმე
კოდურ სიტყვას ყველაფერი დაუჯდეს.

ტანის ბოლო `T * page_body - CODEWORD * m` ბაიტი (`CODEWORD`-ზე ნაკლები)
არცერთ კოდურ სიტყვას არ ეკუთვნის და შევსებაა.

ვექტორები: `tests/vectors/py/container.json`.

### 4.7 შევსება { #47-padding }

შევსება არაფერს ატარებს. არსებობს ორი შიგთავსი და ორივე მართებულია:

- optar 0.3.0 წერდა ნულოვან ბაიტებს;
- optar 0.3.1 და უფრო ახალი წერს **შევსების ნაკადს**: მისი ბლოკი `n`,
  `n = 0, 1, 2, ...`, არის ერთი ბაიტური სტრიქონის SHA-256-ის `PADDING_BLOCK` ბაიტი:
  ეს სტრიქონი არის `PADDING_KEY`, რომელსაც ბოლოში მიწერილი აქვს `n` 8-ბაიტიანი
  მთელი რიცხვის სახით, big-endian რიგით; ნაკადი არის
  შეერთებული ბლოკები. მონაცემთა ზონის შევსება არის ნაკადი მისი 0 ბაიტიდან;
  ტანის ბოლოს შევსება აგრძელებს ნაკადს იქიდან, სადაც მონაცემთა ზონის შევსება
  შეწყდა. (ნულოვანი ბაიტები ყოველ გვერდზე თეთრ ხაზებად იბეჭდება; ნაკადი
  მონაცემების მსგავსად იბეჭდება.)

დოკუმენტი, რომლის შევსებაც სხვა რამეა, წამკითხავი პროგრამისთვის მაინც
მართებული დოკუმენტია (განყოფილება 6.4), მაგრამ მხოლოდ შევსების ნაკადი იძლევა
იმ გვერდებს, რომლებსაც ეს პროექტი ბეჭდავს.

```example
padding_block_0 = d518824e181c15b2f69e390066efbfa00d73eb8f0c3d932313396940eedd1286
padding_bytes_30_to_33 = 12863e00
```

### 4.8 გვერდების რაოდენობა და ზღვრები { #48-the-page-count-and-the-limits }

დოკუმენტს აქვს გვერდების უმცირესი რაოდენობა, რომელიც იტევს ფაილს, სიგრძის
ბაიტსა და სახელს:

    need = size + 1 + L
    T    = the smallest T >= 1 with D(T) >= need

ზღვრებია:

- `T <= MAX_PAGES`;
- `parity > 0`-ის დროს: `T * page_bytes <= PROTECTED_MAX_BYTES`;
- `size < 2^64`, `L <= NAME_MAX_BYTES`.

ფაილი, რომელსაც მეტი სჭირდება, დოკუმენტში ვერ მოთავსდება.

```example

plan_codewords_needed = 4485
plan_pages = 6
plan_codewords = 4696
plan_data_bytes = 1047208
plan_body_bytes = 1197498
plan_spare_bytes = 18
plan_padding_in_region = 47197
plan_position_of_codeword_0_byte_0 = 0
plan_position_of_codeword_5_byte_0 = 5
plan_position_of_codeword_5_byte_1 = 7924
plan_position_of_codeword_5_byte_254 = 1194327
plan_page_of_codeword_5_byte_254 = 6
```

მაგალითი არის 1000000 ბაიტიანი ფაილი სახელით `vector.bin` სტანდარტულ A4
გვერდებზე, ლუწობით 32. მას სჭირდება 4485 კოდური სიტყვა; ხუთი გვერდი ნაკლებს
იტევს, ექვსი კი — `m = 4696`-ს. დოკუმენტს აქვს ყველა 4696 კოდური სიტყვა; ის
კოდური სიტყვები, რომლებიც ფაილს არ სჭირდება, შევსებას შეიცავს.

### 4.9 რას უძლებს დოკუმენტი (ინფორმაციული) { #49-what-the-document-withstands-informative }

დაკარგული გვერდი კოდურ სიტყვას არაუმეტეს `ceil(page_body / m) + 1` ბაიტი
უჯდება. ეს პროექტი თავის მომხმარებელს ეუბნება, რომ დოკუმენტს ნებისმიერი `n`
გვერდის დაკარგვა შეუძლია, როცა
`n * (ceil(page_body / m) + 1) <= PROMISE_NUM * parity // PROMISE_DEN`, რაც
ლუწობის მეოთხედს ტოვებს დარჩენილ გვერდებზე არსებული დაზიანებისთვის. ეს
პროგრამების დაპირებაა და არა თვისება, რომელსაც წამკითხავი პროგრამა შეიძლება
დაეყრდნოს ან რომელიც მან უნდა აკონტროლოს.

### 4.10 კონტეინერიდან გვერდებამდე { #410-from-the-container-to-pages }

ნაკადი არის `T * net_bits // 8` ბაიტი. თუ მას ბიტურ სტრიქონად წავიკითხავთ,
გვერდის `p` (1-დან) სასარგებლო დატვირთვა იწყება ბიტ `(p - 1) * net_bits`-ზე;
ნაკადის ყოველი ბიტი, რომელიც არცერთ სასარგებლო დატვირთვაში არ ხვდება, 0-ია. როცა `net_bits` 8-ის ჯერადია, ნაკადი უბრალოდ
შეერთებული სასარგებლო დატვირთვებია. როცა ასე არ არის, ყოველ გვერდს თავისი
სასარგებლო დატვირთვის შემდეგ აქვს `net_bits mod 8` გამოუყენებელი ბიტი, და
ზოგიერთი გვერდის სასარგებლო დატვირთვა ნაკადის ბაიტის დასაწყისიდან არ
იწყება.

ნაკადი იბეჭდება ისე, როგორც 2.7 განყოფილება ამბობს, რაც ზუსტად `T` გვერდს
იძლევა. გვერდის წარწერა ჩვეულებრივი წარწერის სტრიქონია, რომლის თავისუფალი
ტექსტიც ადამიანებისთვისაა: ეს არის მომხმარებლის მიერ მიცემული წარწერა,
ან, თუ ასეთი არ არის, სახელი, რომელსაც პროგრამა თავად ირჩევს (ფანჯარა
ფაილის სახელს იყენებს, ბრძანების სტრიქონი — `-o`-ით მიცემულ სახელს, რომელიც
შეიძლება ცარიელი იყოს), ყოველ გვერდზე ერთნაირი, და ჭდეს არ ატარებს.
(მართებული ჭდის გამო წამკითხავი პროგრამა გვერდს ჭდიანი დოკუმენტის გვერდად
მიიჩნევდა, განყოფილება 6.1.)

გოლეის კოდის შემთხვევაში `net_bits mod 8` არის 0 ან 4, და ბოლო სასარგებლო
დატვირთვა ყოველთვის ნაკადის შიგნით მთავრდება. ეს პროექტი თვითამოცნობად
დოკუმენტებს მხოლოდ 5.2 განყოფილების ათ გვერდის ფორმატში ბეჭდავს, და მისი
წამკითხავი პროგრამა თავსართებს მხოლოდ ამ ფორმატებში ეძებს.

```example
a4_medium_stream_bytes_for_3_pages = 344713
a4_medium_page_2_starts_at = 114904, 4
a4_medium_page_3_starts_at = 229809, 0
```

`0-50-70-24-3-1-2-24` ფორმატის გვერდს აქვს `net_bits = 919236`, რაც მისი
114904 სასარგებლო დატვირთვის ბაიტის შემდეგ 4 ბიტს ტოვებს. ორი მნიშვნელობა
არის ნაკადის ის ბაიტი, რომელშიც გვერდის სასარგებლო დატვირთვა იწყება, და ბიტი
ამ ბაიტის შიგნით (0 უფროსი ბიტია).

ვექტორები: `tests/vectors/py/container.json`, `tests/vectors/c/container_pages.json`.

### 5.3 PDF, რომელსაც ეს პროექტი წერს { #53-the-pdf-this-project-writes }

დოკუმენტის ყოველი გვერდი PDF-ის ერთი გვერდია, რომლის media box ქაღალდია:
`[0 0 width height]`, ქაღალდის სიგანითა და სიმაღლით პუნქტებში. გვერდის გამოსახულება არის ერთი გამოსახულება,
1 ბიტი პიქსელზე (1 თეთრია), `width`-ზე `height` გვერდის პიქსელი,
ინტერპოლაციის გარეშე, დახატული ისე, რომ მისი ქვედა მარცხენა კუთხე
განლაგების წანაცვლებებზეა, და მასშტაბირებული ისე, რომ გვერდის ერთი პიქსელი
ერთი მონაცემთა წერტილი იყოს:

    image width in points  = width  * dot size in points
    image height in points = height * dot size in points

```example
a4_large_image_width_pt = 560.16
a4_large_image_height_pt = 802.08
```

PDF განკუთვნილია რეალური ზომით (100%) დასაბეჭდად. PDF-ს არცერთი ვექტორი
არ აფიქსირებს; მას აფიქსირებს `tests/unit/test_pdf.py`.

გვერდის გამოსახულებები ასევე იწერება PNG ან PGM ფაილებად, გამოსახულების
ერთი პიქსელით გვერდის თითო პიქსელზე; ვექტორები გვერდს ამოიცნობენ მისი
ორობითი PGM (`P5`) ფაილის SHA-256-ით, რომლის ზუსტ ბაიტებს იძლევა
`tests/vectors/README.md`: თავსართი `P5\n<width> <height>\n255\n` ASCII-ში,
შემდეგ პიქსელების ბაიტები სტრიქონ-სტრიქონ.

### 5.4 წარწერის ლენტი { #54-the-label-strip }

წარწერა იხატება გვერდის პიქსელებში (განყოფილება 2.8), ამიტომ უფრო დიდი
წერტილების გვერდზე იგი ნაკლებ ნიშანს იტევს: ყველაზე დიდი წერტილებით — იმაზე ნაკლებს,
ვიდრე მისი საკუთარი ფორმატის სტრიქონშია. ამიტომ PDF-ში იმ განლაგების
გვერდს, რომლის წერტილის ზომაც `standard` არ არის, წარწერა ჩანაცვლებული აქვს
**წარწერის ლენტით** — მეორე გამოსახულებით, რომელიც სტანდარტული მონაცემთა
წერტილებითაა დახატული:

- ლენტი არის `LABEL_HEIGHT` სტრიქონი და
  `floor(data_width * printer dots per data dot / STANDARD_PRINTER_DOTS)`
  სვეტი ლენტის პიქსელებისა;
- იგი შეიცავს გვერდის წარწერის სტრიქონს, რომელიც მოჭრილი და დახატულია 2.8
  განყოფილების მიხედვით, `data_width`-ის ნაცვლად ლენტის სიგანით;
- გვერდის გამოსახულებაში წარწერის ზოლი შავდება სვეტებში `border`-დან
  `border + data_width - 1`-მდე;
- ლენტი ზოლის თავზე იხატება 0.36 pt-ით ლენტის თითო პიქსელზე, ისე რომ მისი
  მარცხენა კიდე ზოლის მონაცემთა სვეტების მარცხენა კიდეს ემთხვევა, ხოლო
  ზოლის სიმაღლეში იგი ცენტრშია.

მე-2 ნაწილის გვერდისგან მხოლოდ წარწერის ზოლი განსხვავდება; მონაცემთა არე და
ჩარჩო ხელუხლებელია. ასეთი განლაგების PNG ან PGM გვერდი 2.8 განყოფილების
წარწერას ინარჩუნებს. თვითამოცნობადი გვერდის წარწერა მის ამოსაცნობად არ
გამოიყენება (განყოფილება 6.2), ამიტომ საჭირო არ არის, რომ წამკითხავმა
პროგრამამ ლენტი წაიკითხოს.


## 6. რა უნდა გააკეთოს წამკითხავმა პროგრამამ { #6-what-a-reader-must-do }

წამკითხავ პროგრამას აქვს დასკანერებული გვერდები და ნებისმიერი მეთოდით
წაიკითხა თითოეული მათგანის მონაცემთა ბიტები და, სადაც შეძლო, წარწერა. ეს
ნაწილი ამბობს, რა დასკვნა უნდა გამოიტანოს მან მათგან. სკანები არასანდოა:
ერთი გვერდის დაბეჭდვა ნებისმიერს შეუძლია და გვერდს ნებისმიერი რამის
განცხადება შეუძლია.

### 6.1 მართებული ჭდე თავსართს სჯობს { #61-a-valid-tag-wins-over-a-header }

`standard` განლაგების გვერდისთვის წამკითხავმა პროგრამამ ჯერ წარწერას უნდა
შეხედოს. თუ წარწერას 2.8 განყოფილების ფორმა აქვს, ატარებს განლაგების
ფორმატის სტრიქონს, გვერდების რაოდენობას, რომელიც არაუმეტეს `MAX_PAGES`-ია,
გვერდის ნომერს 1-დან გვერდების რაოდენობამდე (ან 1-ს, როცა გვერდების
რაოდენობა 0-ია), და მისი თავისუფალი ტექსტი იწყება ჭდით, რომელიც მართებულია
ამ გვერდის ნომრისა და რაოდენობისთვის (განყოფილება 3.2), გვერდი ჭდიანი
დოკუმენტის გვერდია. იგი ასეთად უნდა იქნეს მიჩნეული მაშინაც კი, თუ მისი
მონაცემები მისაღებ თავსართს (განყოფილება 6.2) შეიცავს.

მიზეზი: თვითამოცნობადი დოკუმენტის ნაკადი, ისეთი, როგორსაც მას ძველი
პროგრამა აბრუნებს, შესაძლებელია ხელახლა დაიბეჭდოს ჭდიან დოკუმენტად. ასეთი
გვერდები თავიანთ მონაცემებში ძველ თავსართებს შეიცავს, და ისინი იმ ჭდიანი
დოკუმენტის გვერდებია, რომლის ფაილიც ეს ნაკადია.

### 6.2 თავსართი არასანდოა { #62-a-header-is-untrusted }

თავსართის ასლი **სწორად აგებულია**, როცა მისი CRC სწორია, მისი სიგნატურა
არის `HEADER_MAGIC`, ვერსია — `CONTAINER_VERSION`, ლუწობა — 0, 32 ან 64, და
`1 <= page <= total`.

**გვერდის თავსართი** არსებობს, როცა მისი `HEADER_COPIES` ასლიდან ერთი მაინც
სწორად აგებულია და ყველა სწორად აგებული ასლი ერთნაირია. გვერდს, რომლის
სწორად აგებული ასლებიც ერთმანეთისგან განსხვავდება, თავსართი არ აქვს.

`F` ფორმატის გვერდიდან წაკითხული თავსართი **მისაღებია**, როცა იგი აღწერს
დოკუმენტს, რომელსაც 4.8 განყოფილება უშვებს, ანუ როცა ყველა ეს პირობა
სრულდება (`m`, `D` და `page_bytes` — 4.1 განყოფილების მიხედვით, `F`-ისა და
თავსართის ლუწობისთვის):

1. `total <= MAX_PAGES`;
2. `page_bytes // HEADER_COPIES >= HEADER_SIZE`;
3. თუ `parity > 0`: `total * page_bytes <= PROTECTED_MAX_BYTES`;
4. `size + 1 <= D(total)`: გვერდები იტევს ფაილს და სიგრძის ბაიტს;
5. თუ `total > 1`: `size + 1 + NAME_MAX_BYTES > D(total - 1)`: არცერთი სახელი
   არ მისცემდა ფაილს ნაკლებ გვერდზე მოთავსების საშუალებას.

წამკითხავმა პროგრამამ არ უნდა გამოიყენოს თავსართი, რომელიც მისაღები არ არის.
წესები 4 და 5 გვერდების რაოდენობას ზომას უკავშირებს, ისე რომ თავსართმა ვერ
განაცხადოს ბევრი გვერდი პატარა ფაილისთვის ან დიდი ფაილი ცოტა გვერდზე.

წამკითხავმა პროგრამამ თავისი მეხსიერებისა და დროის ხარჯი უნდა შეინარჩუნოს
მისთვის მიცემული გვერდების პროპორციულად და არა იმისა, რასაც თავსართი
აცხადებს: ერთმა გვერდმა, რომელიც 9999-გვერდიან დოკუმენტს აცხადებს, არ უნდა
აიძულოს წამკითხავი პროგრამა, 9999 გვერდისთვის გამოყოს მეხსიერება ან 9999
გვერდი დაამუშაოს.

გვერდები ერთ დოკუმენტს ეკუთვნის, როცა მათი თავსართები ერთმანეთს ემთხვევა
`fingerprint`, `size`, `total` და `parity` ველებში და გვერდებს ერთი და იგივე
გვერდის ფორმატი აქვს. სხვა დოკუმენტის გვერდები არ უნდა იქნეს გამოყენებული.

### 6.3 ფაილს მხოლოდ ანაბეჭდი ამოწმებს { #63-only-the-fingerprint-verifies-a-file }

- **თვითამოცნობადი დოკუმენტი.** სასარგებლო დატვირთვის ბაიტი წაშლილი
  ბაიტია (erasure), როცა მისი ერთ-ერთი ბიტი მდებარეობს სიმბოლოში, რომლის
  შესწორებაც გვერდის კოდმა ვერ შეძლო; იმ გვერდის ყოველი ბაიტი, რომელიც არ
  იქნა მიწოდებული, წაშლილი ბაიტია. ფაილი არის მონაცემთა ზონის პირველი
  `size` ბაიტი, და იგი აღდგენილია მაშინ და მხოლოდ მაშინ, როცა ყოველი კოდური
  სიტყვა, რომელიც ამ ბაიტებიდან ერთს მაინც შეიცავს, წაკითხულია ან
  გამოსწორებულია (ლუწობა 0-ის დროს, როცა გამოსწორება საერთოდ არ ხდება,
  პირობა ასეთია: არცერთ ასეთ კოდურ სიტყვას წაშლილი ბაიტი არ აქვს). ფაილი **შემოწმებულია**, როცა
  იგი აღდგენილია და მისი SHA-256-ის პირველი `FINGERPRINT_SIZE` ბაიტი
  თავსართის ანაბეჭდს უდრის.
- **ჭდიანი დოკუმენტი.** ფაილი არის ნაკადის პირველი `SIZE` ბაიტი. იგი
  **შემოწმებულია**, როცა მას `SIZE` ბაიტი აქვს და მისი SHA-256-ის პირველი
  `FINGERPRINT_DIGITS` თექვსმეტობითი ნიშანი ჭდის ანაბეჭდს უდრის.
- **მარტივი დოკუმენტი.** მას ვერაფერი ამოწმებს, და მისი სიგრძე ცნობილი არ
  არის (განყოფილება 2.7).

წამკითხავმა პროგრამამ ფაილს შემოწმებული არ უნდა უწოდოს რაიმე სხვა
მიზეზით. კერძოდ, გამოსწორება, რომელიც მარცხს არ აცხადებს, ფაილს არ
ამოწმებს: კოდური სიტყვა, რომელშიც იმაზე მეტი არასწორი ბაიტია, ვიდრე მის
ლუწობას შეუძლია გამოასწოროს, შეიძლება სხვა მართებულ კოდურ სიტყვად იქცეს,
ხოლო ლუწობა 0-ის დროს საერთოდ არაფერი კონტროლდება.

ფაილის სახელი (განყოფილება 4.6) ანაბეჭდის მიღმაა. იგი არასანდო ტექსტია
მაშინაც კი, როცა ფაილი შემოწმებულია, ისევე როგორც ყოველი წარწერა.

### 6.4 შევსება არასოდეს იკითხება { #64-padding-is-never-read }

წამკითხავმა პროგრამამ არ უნდა წაიკითხოს 4.7 განყოფილების შევსება, არ უნდა
გააკონტროლოს იგი და არ უნდა იყოს მასზე დამოკიდებული. ნულოვანი ბაიტებიც
(0.3.0) და შევსების ნაკადიც (0.3.1) მართებულია, და დოკუმენტი რომელიმე
მათგანით წამკითხავი პროგრამისთვის ერთი და იგივე დოკუმენტია.

მონაცემთა ზონის ბაიტები სახელის შემდეგ შევსებაა. სახელის ჩანაწერი, რომლის
სიგრძის ბაიტიც მონაცემთა ზონის დასასრულს მიღმა მიუთითებს, ან რომლის
ბაიტებიც UTF-8 არ არის, ან რომელიც მდებარეობს კოდურ სიტყვაში, რომელიც არ
გამოსწორდა, სახელს არ იძლევა; ეს ფაილს არამართებულს არ ხდის.

ვექტორები: `tests/vectors/py/container.json`, `tests/vectors/py/tag.json`.

## 7. საცნობარო დეკოდერი (ინფორმაციული) { #7-reference-decoder-informative }

ეს ნაწილი აღწერს, როგორ კითხულობს ეს პროექტი სკანს. აქედან არაფერია
სავალდებულო: წამკითხავმა პროგრამამ შეიძლება გვერდი ნებისმიერი გზით იპოვოს
და მისგან ნიმუშები ნებისმიერი გზით აიღოს. ნაბიჯები და მათი მუდმივები C-ზე
დაწერილი პროგრამის, `unoptar`-ისაა (ნაწილი 8); ამ დეკოდერის შედეგებს
ფიქსირებულ სკანებზე აფიქსირებს ბოლოს დასახელებული ვექტორები, რათა იგი
შემთხვევით არ შეიცვალოს.

### 7.1 სკანი { #71-the-scan }

სკანი იკითხება როგორც 8-ბიტიანი ნაცრისფერი გამოსახულება წრფივ სინათლეში.
ფაილის ნიმუში `v` გადაიქცევა `floor(255 * (v / 255) ^ (1 / gamma) + 0.5)`-ად,
სადაც `gamma` არის ფაილის გამა (PNG `gAMA`) ან 0.454545, როცა ფაილი მას არ
იძლევა. ფერადი გამოსახულება გარდაიქმნება არხ-არხ და შემდეგ იწონება წონებით
0.212671 წითელი, 0.715160 მწვანე, 0.072169 ლურჯი, უახლოეს მთელ რიცხვამდე
დამრგვალებით. 16-ბიტიანი ნიმუში თავის ზედა 8 ბიტს ინარჩუნებს.

```example
linear_light_of_128 = 56
linear_light_of_200 = 149
```

### 7.2 გვერდის პოვნა { #72-finding-the-page }

დეკოდერს გვერდის ფორმატი მიეცემა. იგი მუშაობს სწორ მდებარეობაში მყოფ
გამოსახულებაზე.

1. **ნაცრისფრის დონეები.** ზღურბლი იწყება ნაცრისფრის საშუალო მნიშვნელობით.
   არაუმეტეს 32-ჯერ: `black` არის ზღურბლს გამოკლებული ზღურბლის ქვემოთ
   მყოფი პიქსელების მისგან მანძილების საშუალო კვადრატული მნიშვნელობა
   (კვადრატების საშუალოდან აღებული კვადრატული ფესვი), `white` — ზღურბლს
   დამატებული იგივე სიდიდე ზღურბლის ზემოთ მყოფი პიქსელებისთვის; ახალი
   ზღურბლია `sync_white_cut * white + (1 - sync_white_cut) *
   black`, დამრგვალებული; პროცესი ჩერდება, როცა ზღურბლი აღარ იცვლება. მეორე
   დონე, დატბორვის ზღურბლი, `black`-სა და `white`-ს შუაშია.
2. **გვერდის გამოყოფა.** გვერდის გარშემო თეთრი არის ყოველი პიქსელი
   დატბორვის ზღურბლზე ან მის ზემოთ, რომელიც (კიდეებით და არა კუთხეებით)
   დაკავშირებულია სკანის ოთხი კუთხიდან ან ოთხი კიდის შუაწერტილიდან
   ერთ-ერთთან. გვერდი არის ყველაფერი დანარჩენი, რაც სკანის ცენტრთანაა
   დაკავშირებული. ყველა სხვა პიქსელი (ჭუჭყი გვერდსა და სკანის კიდეს შორის)
   თეთრდება.
3. **ხარვეზი ჩარჩოში.** თუ პრინტერმა გვერდის კიდე მოჭრა, ჩარჩოს ხარვეზი
   აქვს, გვერდის გარშემო თეთრი წერტილებს შორის შედის და ნაბიჯი 2 გვერდის
   მხოლოდ ნაწილს პოულობს. როცა ნაპოვნი ფართობი იმის ნახევარზე ნაკლებია, რაც
   გვერდის გარშემო თეთრს, როგორც ის ნაბიჯმა 2 იპოვა, არ მიეკუთვნება, გვერდის გარშემო თეთრად ამის ნაცვლად მიიჩნევა
   ის, რაც მიღწევადია სულ მცირე `2 * r + 1` პიქსელი სიგანის გასასვლელებით,
   სადაც `r = max(5, longest side // 250) // 2`; წერტილებს შორის თეთრი ამაზე
   ვიწროა. ეს შედეგი გამოიყენება მხოლოდ მაშინ, თუ იგი მთელ გვერდს იძლევა.
   ეს ამ დეკოდერის შემწყნარებლობაა და არა ფორმატის თვისება: გვერდს მთელი ჩარჩო
   აქვს.
4. **კუთხეები.** სკანის ყოველი კუთხიდან დეკოდერი დიაგონალებს შიგნით მიუყვება
   და იღებს პირველ პიქსელს ზღურბლის ქვემოთ. ამას სჭირდება, რომ გვერდი სწორ
   მდებარეობაში იყოს და სიგანეზე მაღალი; სკანი, რომელიც სიმაღლეზე განიერია,
   ჯერ შემობრუნდება (7.5).
5. **პიქსელის ზომა.** სკანის პიქსელები გვერდის პიქსელზე, ჰორიზონტალურად და
   ვერტიკალურად, მიიღება კუთხეებს შორის მანძილების `width`-სა და
   `height`-ზე გაყოფით; გვერდის სტრიქონებისა და სვეტების მიმართულებები
   მიიღება მოპირდაპირე მხარეების საშუალოებიდან. (ჰორიზონტალური ზომა ზედა
   მარცხენა კუთხეს ორჯერ იყენებს, ქვედა მარცხენას კი საერთოდ არ იყენებს. ეს
   დეკოდერის მემკვიდრეობითი ქცევაა და ფორმატის ნაწილი არ არის.)

### 7.3 ჯვრები { #73-crosses }

პირველი ჯვარი მოსალოდნელია ზედა მარცხენა კუთხიდან `border + chalf` გვერდის
პიქსელით შიგნით. ყოველი სხვა ჯვარი მოსალოდნელია თავისი მარცხენა მეზობლიდან
ერთი ბიჯით მარჯვნივ, ხოლო სტრიქონის პირველი ჯვარი — მის ზემოთ მყოფიდან ერთი
ბიჯით ქვემოთ, ამიტომ ყოველი ძებნა უკვე ნაპოვნი ჯვრიდან იწყება. ყოველი
ჯვრისთვის:

1. უხეში ძებნა სკანის მთელი პიქსელებით, ყოველი მიმართულებით ჯვრის მხარის
   ნახევრის (`chalf`) ნახევრამდე, იმ ადგილისთვის, სადაც გამოსახულება საუკეთესოდ კორელირებს
   ჯვრის სურათთან (მუქი, ღია, ღია, მუქი);
2. ზუსტი ძებნა სკანის ნახევარი პიქსელის ფარგლებში მეოთხედი პიქსელის
   ნაბიჯით, ჯვარზე, რომელიც ყოველ მხარეს `cross_trim` გვერდის პიქსელით არის
   შემცირებული;
3. საკუთარი ზღურბლი: ჯვრის პიქსელებიდან `white` და `black`, როგორც 7.2-ში,
   გაერთიანებული როგორც `white_cut * white + (1 - white_cut) * black`.

### 7.4 ნიმუშების აღება და დეკოდირება { #74-sampling-and-decoding }

1. **ფილტრები.** მუქი ლაქები, რომლებიც გვერდის პიქსელის ზომის
   `minmax_filter`-ჯერზე ვიწროა, შორდება (მაქსიმუმის ფილტრის გავლები, შემდეგ
   იმდენივე გავლა მინიმუმის ფილტრისა); შემდეგ გამოსახულება ბუნდოვანდება 3-ზე 3
   ბირთვით (1 2 1 / 2 4 2 / 1 2 1), `round(pixel area * pixel_blur ^ 2)`-ჯერ.
2. **ნიმუშების აღება.** ყოველი მონაცემთა პიქსელის პოზიცია სკანზე
   ინტერპოლირდება მის გარშემო მყოფ ოთხ ჯვარს შორის, ისევე როგორც მისი
   ზღურბლი. ნიმუში მკვეთრდება: `value + unsharp_mask * (value - mean of the four
   neighbours at unsharp_dist page pixels)`. ბიტი არის 1, როცა შედეგი
   ზღურბლზე დაბალია.
3. **დეკოდირება.** ბიტები უკან სიმბოლოებად ლაგდება (განყოფილება 2.6).
   გოლეის სიმბოლო ჩანაცვლდება უახლოესი სიმბოლოთი, თუ ეს უკანასკნელი
   არაუმეტეს 3 ბიტით განსხვავდება; წინააღმდეგ შემთხვევაში სიმბოლო
   შეუსწორებელია და მისი ზედა 12 ბიტი აიღება ისე, როგორც წაკითხულია. ჰემინგის
   სიმბოლოში ერთი არასწორი ბიტი შესწორდება; ორი არასწორი ბიტი მას
   შეუსწორებელს ხდის.
4. გვერდის სიტყვები მის `net_bits` მონაცემთა ბიტად ერთდება. მარტივი ან
   ჭდიანი დოკუმენტისთვის გვერდების ბიტები გვერდების რიგით ერთდება და ბაიტებად
   იჭრება; ბიტები, რომლებიც ბოლო ბაიტს ვერ ავსებს, უგულებელყოფილია.

```example
decoder_unsharp_mask = 7
decoder_unsharp_dist = 1
decoder_sync_white_cut = 0.1
decoder_white_cut = 0.06
decoder_minmax_filter = 0.5
decoder_pixel_blur = 0.25
decoder_cross_trim = 0.75
```

### 7.5 სკანის ამოცნობა { #75-identifying-a-scan }

როცა გვერდის ფორმატი არ ეცნობება, ეს პროექტი მას თავად ადგენს:

1. გვერდის კონტური (7.2, ნაბიჯები 1-დან 4-მდე) იძლევა მის ფორმას. ორივე
   ქაღალდი ისინჯება იმ რიგით, თუ რამდენად ახლოსაა ფორმა მათ `standard`
   გვერდთან; თითოეული ისინჯება სწორ მდებარეობაში და ნახევარი ბრუნით
   შემობრუნებული (ან მეოთხედი ბრუნით რომელიმე მხარეს, სკანისთვის, რომელიც
   სიმაღლეზე განიერია).
2. თითოეული ქაღალდისთვის ჯერ მისი `standard` გვერდი: დგინდება გვერდის
   მდებარეობა და მისი წარწერა იკითხება ყოველი ნიშნის უჯრის შრიფტთან
   შედარებით. მართებული ჭდე მაშინვე წყვეტს საკითხს (განყოფილება 6.1). ჭდის
   გარეშე წარწერა მიიღება მხოლოდ მაშინ, როცა იგი მკაფიოდ იქნა წაკითხული,
   და მაშინაც მონაცემებში მაინც იძებნება თავსართი, რადგან სტანდარტული
   წერტილებით თვითამოცნობად გვერდს ასეთი წარწერა აქვს.
3. შემდეგ ქაღალდის განლაგებები, უახლოესი ფორმიდან დაწყებული: დგინდება
   გვერდის მდებარეობა, გვერდი დეკოდირდება, და საკითხს წყვეტს მისაღები
   თავსართი (განყოფილება 6.2).

არასწორად წაკითხული ჭდის საკონტროლო მნიშვნელობა დაახლოებით 256-დან ერთხელ ემთხვევა; ჭდის გარეშე წარწერას საკონტროლო მნიშვნელობა საერთოდ არ აქვს, რის გამოც იგი
მკაფიოდ უნდა იყოს წაკითხული და რის გამოც უარყოფილია თავისუფალი ტექსტი,
რომელიც მართებული ჭდისგან ერთი არასწორად წაკითხული ნიშნით განსხვავდება.
მიღების ეს ზღურბლები ამ წამკითხავ პროგრამას ეკუთვნის და არა ფორმატს.

### 7.6 წაკითხვის ნელი მეთოდი { #76-the-slower-reader }

ეს პროექტი ორ შემთხვევაში ცდის წაკითხვის მეორე, უფრო ნელ მეთოდს
(`src/optar/decoder/soft.py`), რომელიც განკუთვნილია ისეთი სკანისთვის,
რომლის გარჩევადობაც მისი წერტილის ზომისთვის ზედმეტად დაბალია. პირველი:
7.5-ის ნაბიჯები ვერაფერს ამოიცნობს, თუმცა გვერდის კონტური ნაპოვნია. მეორე:
სრულდება სამივე შემდეგი პირობა: 7.5-ის ნაბიჯები გვერდს მხოლოდ ჭდის გარეშე
წარწერით იღებს; ამ სკანზე მონაცემთა პიქსელის სიგანე სკანის 2.5 პიქსელზე
ნაკლებია; და გვერდის სიმბოლოების 1% ან მეტი შეუსწორებელია. ყოველი კანდიდატი განლაგებისა და ბრუნვისთვის,
7.5-ის რიგით, იგი:

1. ადიდებს სკანს ისე, რომ მონაცემთა პიქსელი სკანის დაახლოებით ოთხი პიქსელის
   სიგანისა იყოს, და ადგენს გვერდის მდებარეობას, როგორც 7.2-სა და 7.3-ში;
2. კითხულობს გვერდს, როგორც 7.4-ში, და ცნობილად მიიჩნევს სიმბოლოებს,
   რომლებიც არაუმეტეს ერთი შესწორებული ბიტით დეკოდირდა;
3. ყოველი მონაცემთა პიქსელის გარშემო იღებს 7-ზე 7 ბადის ნიმუშებს,
   ერთმანეთისგან მონაცემთა პიქსელის ნახევრით დაშორებულს, და უმცირესი
   კვადრატების მეთოდით არგებს ფილტრს, რომელიც ამ ნიმუშებიდან ცნობილ ბიტებს
   იძლევა, თითო ფილტრს გვერდის 16-ზე 22 უბნიდან თითოეულისთვის;
4. ფილტრებს იყენებს ყოველ მონაცემთა პიქსელზე, რაც ყოველი ბიტისთვის
   სანდოობის მნიშვნელობას იძლევა, დადებითს ან უარყოფითს, და გვერდის ყოველი
