# Командний рядок { #command-line }

Команда `optar` кодує файл у сторінки й декодує скани назад. Їй не потрібні ні
компілятор C, ні libpng, ні ImageMagick.

    optar encode INPUT [-o BASE] [--paper a4|letter] [--to pdf|png|pgm] [--label TEXT] [--no-tag]
                 [--dots standard|medium|big|large|xlarge] [--protect none|standard|high]
                 [--compatible] [--format STRING]
    optar decode BASE [-o OUTPUT] [--paper a4|letter] [--format STRING] [--debug-images] [--force]
                 [--no-slow-reader]
    optar --version

## encode { #encode }

`encode` типово записує `BASE.pdf` (типове значення `BASE` — `optar_out`), а з
`--to` — сторінки `BASE_0001.png` (або `.pgm`), `BASE_0002.png`, ...

| Що ви задаєте | Що отримуєте |
|---|---|
| ні `--dots`, ні `--protect`, або `--compatible` | роздруківку, яку зчитують 0.2.0 і програма на C: стандартні точки, без захисту |
| лише `--dots X` | цей розмір точок зі стандартним захистом |
| лише `--protect LEVEL` | стандартні точки з цим захистом |
| `--protect none` | без захисту |

Будь-який із трьох останніх варіантів створює сторінки із самоідентифікацією
(сторінки, які самі повідомляють, до якого документа належать і який мають
номер); щоб їх зчитати, потрібен optar 0.3 або новіший. Наприклад:

    optar encode photo.jpg -o photo --dots large --protect high

Розміри точок і рівні захисту описано в розділі
[Записати файл на папір](put-on-paper.md#dot-size).

Сумісна роздруківка має [мітку](identification.md#the-tag) на кожній
сторінці; щоб її не додавати, вкажіть `--no-tag`.

Типове значення `--paper` — A4.

## decode { #decode }

`decode` зчитує `BASE_0001.png`, `BASE_0002.png`, ... і записує дані у
`-o OUTPUT` або в stdout. Він зчитує лише файли з такими іменами.

Що він робить, залежить від роздруківки. Він вирішує за першими трьома
сканами: якщо жоден із них не вдається розпізнати як сторінку із
самоідентифікацією, набір вважається роздруківкою версії 0.2.0 або ранішої.

### Сторінки із самоідентифікацією { #self-identifying-pages }

`decode` з’ясовує, що це за скани, з самих сканів.

- Він приймає скани в будь-якому порядку й будь-якому положенні.
- Скан, який він не може зчитати, вважається відсутньою сторінкою.
- Скан, який звичайний метод зчитування не може розпізнати, спершу
  передається [повільному методу](slower-reader.md), якщо ви не вказали
  `--no-slow-reader`.
- Він виправляє дані, обрізає їх до справжнього розміру й звіряє з
  відбитком.
- Він записує файл, лише якщо той збігається з відбитком. Виняток — параметр
  `--force`: з ним зберігається те, що вдалося відновити, навіть якщо воно не
  пройшло перевірки. Навіть із `--force` нічого не зберігається, якщо зчитано
  менше половини сторінок.

### Роздруківки версії 0.2.0 або ранішої { #printouts-from-020-or-earlier }

- `--paper` має бути таким самим, як під час кодування.
- Сторінка має бути відсканована в прямому положенні (книжкова орієнтація,
  напис унизу). Альбомні скани тут не підтримуються; це успадковано від
  декодера на C. Настільний застосунок приймає будь-яке положення для будь-якої
  роздруківки.
- `decode` не обрізає результат до розміру з мітки й не звіряє його з
  відбитком: результат завжди доповнено нулями до цілої сторінки. Настільний
  застосунок робить і те, й інше. Якщо для ваших даних це важливо, запакуйте їх
  за допомогою tar.
- `--force` нічого не змінює, і `decode` про це повідомляє.

## Код завершення { #exit-status }

| Код | Що означає |
|---|---|
| 0 | Успіх. Для сторінок із самоідентифікацією: файл пройшов перевірку. |
| 1 | Дані декодовано, але вони не піддаються корекції, або в нумерації сторінок є пропуск, або (для сторінок із самоідентифікацією) файл не пройшов перевірки. |
| 2 | Помилка у використанні команди або у вхідних даних. |

## Код із корекцією помилок { #the-error-correcting-code }

Типово використовується код Голея 24/12. Підтримуються також коди Геммінга
порядків від 2 до 5, які вибирають через `--format` (шосте поле рядка
формату). Рядок формату визначено в [специфікації формату](format.md).
