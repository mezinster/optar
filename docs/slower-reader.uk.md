# Скани з надто низькою роздільною здатністю: повільний метод { #scans-that-are-too-coarse-the-slower-reader }

Починаючи з версії 0.4.0, програма має другий, повільніший метод зчитування
для сканів, зроблених із надто низькою для їхнього розміру точок роздільною
здатністю, наприклад сторінки зі стандартними точками, відсканованої з
300 dpi замість 600.

Коли можете, скануйте з рекомендованою роздільною здатністю. Повільний метод
відновлює деякі скани з низькою роздільною здатністю, але не всі (див.
[Що показано, а що ні](evidence.md#the-slower-reader)).

## Коли він запускається { #when-it-runs }

Він запускається сам, у двох випадках:

- Звичайний метод зчитування не може розпізнати скан, але знаходить на ньому
  контур сторінки.
- Скан із низькою роздільною здатністю (менше ніж 2,5 пікселя скану на точку)
  дав звичайному методу лише напис без мітки й жодного заголовка, а дані
  сторінки зчиталися погано (1% або більше її символів не піддається
  корекції). На такому скані напис ще може бути розбірливим там, де дані вже
  нерозбірливі.

Сторінка, дані якої зчитуються добре, — це стара сторінка без заголовка, і
її не чіпають. Якщо повільний метод нічого не знаходить, залишається те, що
зчитано з напису.

## Як він працює { #how-it-works }

Повільний метод збільшує скан. За точками, у яких звичайний метод упевнений,
він з’ясовує, як сусідні точки розпливаються одна в одну в кожній частині
сторінки. Потім він зчитує кожну точку з урахуванням цього знання й вибирає
кожен символ як ціле.

## У застосунку { #in-the-application }

![Дві сторінки, зчитані повільним методом, на яких позначено скориговані точки](img/slow-pages.png)

*Згенерована тестова сторінка, невелика й відсканована з дуже низькою
роздільною здатністю. Скориговані точки позначено на перегляді.*

- Поки метод працює, рядок скану показує етап повільного методу й хід
  виконання. Якщо вибрати рядок, буде сказано, що це займе близько хвилини.
- Потім у рядку написано, що сторінку зчитано повільним методом і скільки
  точок він скоригував, наприклад: «Сторінка 3 · Зчитана повільним методом ·
  скориговано 265 112 точок». Скоригована точка — це точка, власне зображення
  якої на скані не взяло гору під час вибору її символу.
- Скориговані точки позначено на перегляді скану, кожна позначка завширшки в
  одну точку. На сканах із низькою роздільною здатністю це часто кілька
  відсотків точок, тож якщо дивитися на всю сторінку, вона здається затіненою —
  тим густіше, чим більше точок скориговано. Якщо збільшити масштаб, видно окремі
  точки.
- Коли документ пройде перевірку, рядок додає, скільки байтів сторінки
  виправив захист документа («· захист документа виправив 6 912 байтів»).
  Якщо вибрати сторінку, буде показано обидва числа.

Таку сторінку ніколи не називають «Справна», а в рядку внизу її враховують
окремо. Повільний метод дає для кожного символу найкраще припущення, тож не
може сказати, що на сторінці не піддається виправленню.

## У командному рядку { #on-the-command-line }

`optar decode` теж запускає його сам і повідомляє про це в stderr для кожного
скану, до якого його застосовано. `--no-slow-reader` вимикає його.

## Скільки це триває { #how-long-it-takes }

На комп’ютері розробника обробка сторінки A4 загалом тривала від 40 до 70 секунд: від
20 до 35 секунд, поки звичайний метод не здасться, а потім від 20 до 35 секунд
на повільний метод.

Зображення, яке взагалі не є сторінкою optar, але на якому знайдено контур
сторінки, обробляється приблизно на 20–35 секунд довше, ніж без повільного
методу.

## Обмеження { #limits }

- Він розпізнає сторінку лише за заголовком у її даних. Старі сторінки у
  стилі версії 0.2, які розпізнаються за міткою в написі, він не охоплює.
- Сторінка, мітку якої прийняв звичайний метод, ніколи не передається
  повільному методу.
- Очікується, що стандартного захисту не вистачить для сторінки зі
  стандартними точками, відсканованої приблизно з 290 dpi. Єдиний справжній
  документ, який вдалося так відновити, мав високий захист і потребував
  більшого виправлення, ніж може дати стандартний захист.
- Він не робить неправильний файл схожим на правильний: як і завжди,
  перевіреним файл робить лише відбиток.
