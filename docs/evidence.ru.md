# Что показано, а что нет { #what-has-and-has-not-been-shown }

В этом разделе сказано, на чём основаны утверждения проекта. Бо́льшая часть
из них получена на имитированных сканах, а не на бумаге.

## Имитированные сканы { #simulated-scans }

Автоматические тесты читают сгенерированные изображения с размытием, шумом и
поворотом. Имитируемое размытие подобрано по трём реальным сканам 300 dpi
одной напечатанной страницы, сделанным на одном принтере и одном протяжном
сканере.

- При таком размытии стандартные точки при 300 dpi обычным методом чтения не
  декодировались.
- Средние точки со стандартной защитой прошли проверку при 300 dpi и при
  200 dpi.
- Большие, крупные и очень крупные точки прошли проверку при 200 dpi без
  ошибок.
- Документ из 12 страниц прошёл проверку, когда одна страница была изъята.

## Медленный метод { #the-slower-reader }

Работа [медленного метода](slower-reader.md) показана на одном реальном
документе и на одном имитированном.

**Реальный.** Документ владельца проекта из шести страниц A4, стандартные
точки, высокая защита, отсканирован примерно при 290 dpi, хотя рекомендуется
600 dpi. Обычный метод не опознал ни одной страницы. С медленным методом файл
был восстановлен и проверен по отпечатку: 759 879 байт, из которых 41 495 байт
исправила защита документа; в худшем блоке израсходовано 40 из 64 единиц
ресурса исправления. Это один документ, один принтер, один сканер и одно разрешение. Сканов
в репозитории нет.

**Имитированный** (`tests/unit/test_coarse_claim.py`). Документ из двух
страниц того же вида, отсканированный при 290 и при 300 dpi с размытием
1,8 точки принтера. При 290 dpi обычный метод не опознаёт ни одной страницы;
при 300 dpi он читает надпись каждой страницы, но не заголовок. В обоих
случаях файл проходит проверку с медленным методом. При размытии имитатора по
умолчанию (1,0) обычный метод сам читает такую страницу при 300 dpi.

Имитатор мягче сканера владельца: при 290 dpi в имитации медленный метод
ничего не исправлял, тогда как реальному документу понадобилось исправить
41 495 байт.

Ресурс стандартной защиты — 32, меньше тех 40, которые понадобились худшему
блоку реального документа. Поэтому ожидается, что документ со стандартной
защитой, отсканированный так же, восстановить не удастся. Старые страницы в
стиле 0.2 медленный метод не охватывает.

## Что не показано { #what-is-not-shown }

- Ни одного реального скана страницы с более крупными точками пока не
  прочитано.
- Для чтения надписей и декодирования есть автоматические тесты только на
  синтетических сканах, а не на реальных напечатанных и отсканированных
  страницах. Это касается и всех распечаток с более крупными точками или с
  защитой.
- Протяжные сканеры не испытывались, кроме того что программа нашла сетку
  точек на трёх реальных сканах.
- Три реальных скана 300 dpi одной распечатки при измерении дали около
  286 dpi, а значит, эта распечатка вышла примерно в 95% натуральной величины.
  Мелкие точки труднее читать, поэтому печатайте в натуральную величину
  (100%).
- Струйные принтеры не испытывались.

## Те же страницы, что у программы на C { #the-same-pages-as-the-c-program }

Страницы кодировщика на Python побайтно совпадают с результатом
первоначальной программы `optar` на C для A4, Letter и всех пяти режимов
коррекции ошибок. Положения крестов и считанные биты декодера на Python
побитно совпадают с `unoptar` на C на синтетических тестовых изображениях. И
то, и другое сравнивается с результатами программ на C, которые были записаны
один раз и хранятся в `tests/vectors`.

Каждая страница самоопознающейся распечатки (страницы которой сами сообщают,
к какому документу они относятся и какой у них номер) остаётся обычной
страницей optar: `unoptar` на C, собранный с тем же размером сетки, точно
читает её точки (записано для крупных точек на A4 и средних точек на Letter).
Возвращает он при этом данные, в которых файл обёрнут дополнительными
сведениями и защитой, а не сам файл.
