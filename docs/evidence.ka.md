# რა არის ნაჩვენები და რა — არა { #what-has-and-has-not-been-shown }

ეს განყოფილება აღწერს, რას ეყრდნობა პროექტის მტკიცებები. მისი უმეტესი ნაწილი
სიმულირებულ სკანებს ეფუძნება და არა ქაღალდს.

## სიმულირებული სკანები { #simulated-scans }

ავტომატური ტესტები კითხულობს გენერირებულ გამოსახულებებს გაბუნდოვნებით,
ხმაურითა და მობრუნებით. სიმულირებული გაბუნდოვნება მორგებულია ერთი დაბეჭდილი
გვერდის სამ რეალურ 300 dpi სკანზე, რომლებიც გაკეთდა ერთი პრინტერითა და
ფურცლების ავტომატური მიწოდების ერთი სკანერით.

- ამ გაბუნდოვნებისას სტანდარტული წერტილები 300 dpi-ზე წაკითხვის ჩვეულებრივი
  მეთოდით არ დეკოდირდა.
- საშუალო წერტილებით და სტანდარტული დაცვით ფაილმა შემოწმება გაიარა
  300 dpi-ზეც და 200 dpi-ზეც.
- დიდი, მსხვილი და ძალიან მსხვილი წერტილებით ფაილმა შემოწმება 200 dpi-ზე
  უშეცდომოდ გაიარა.
- 12-გვერდიანმა დოკუმენტმა შემოწმება გაიარა მაშინაც, როცა ერთი გვერდი
  განზრახ იყო გამოტოვებული.

## წაკითხვის ნელი მეთოდი { #the-slower-reader }

[წაკითხვის ნელი მეთოდი](slower-reader.md) ნაჩვენებია ერთ რეალურ და ერთ
სიმულირებულ დოკუმენტზე.

**რეალური.** პროექტის მფლობელის დოკუმენტი: ექვსი A4 გვერდი, სტანდარტული
წერტილები, მაღალი დაცვა, დასკანერებული დაახლოებით 290 dpi გარჩევადობით, მაშინ
როცა რეკომენდებულია 600 dpi. წაკითხვის ჩვეულებრივმა მეთოდმა ვერცერთი გვერდი
ვერ ამოიცნო. ნელი მეთოდით ფაილი აღდგა და ანაბეჭდით შემოწმება გაიარა:
759 879 ბაიტი, რომელთაგან 41 495 ბაიტი დოკუმენტის დაცვამ გამოასწორა, ხოლო
ყველაზე უარესმა ბლოკმა თავისი გამოსწორების რესურსის 64-დან 40 გამოიყენა. ეს
არის ერთი დოკუმენტი, ერთი პრინტერი, ერთი სკანერი და ერთი გარჩევადობა. სკანები
რეპოზიტორიის ნაწილი არ არის.

**სიმულირებული** (`tests/unit/test_coarse_claim.py`). იმავე ტიპის
ორგვერდიანი დოკუმენტი, დასკანერებული 290 და 300 dpi გარჩევადობით,
1,8 პრინტერის წერტილის გაბუნდოვნებით. 290 dpi-ზე ჩვეულებრივი მეთოდი ვერცერთ
გვერდს ვერ ამოიცნობს; 300 dpi-ზე ის თითოეული გვერდის წარწერას კითხულობს,
მაგრამ თავსართს — ვერა. ორივე შემთხვევაში ფაილი ნელი მეთოდით შემოწმებას
გადის. სიმულატორის ნაგულისხმევი გაბუნდოვნებისას (1,0) ჩვეულებრივი მეთოდი
ასეთ გვერდს 300 dpi-ზე დამოუკიდებლად კითხულობს.

სიმულატორი მფლობელის სკანერზე რბილია: სიმულაციაში 290 dpi-ზე ნელ მეთოდს
არაფერი გამოუსწორებია, მაშინ როცა რეალურ დოკუმენტს 41 495 ბაიტის
გამოსწორება დასჭირდა.

სტანდარტული დაცვის გამოსწორების რესურსი 32-ია, რაც ნაკლებია იმ 40-ზე,
რომელიც რეალური დოკუმენტის ყველაზე უარეს ბლოკს დასჭირდა. ამიტომ
მოსალოდნელია, რომ ასე დასკანერებული სტანდარტული დაცვის დოკუმენტი ვერ აღდგება.
ძველი, 0.2-ის სტილის გვერდები ნელი მეთოდის ფარგლებში არ ხვდება.

## რა არ არის ნაჩვენები { #what-is-not-shown }

- უფრო მსხვილი წერტილების გვერდის არცერთი რეალური სკანი ჯერ არ წაკითხულა.
- წარწერების წაკითხვას და დეკოდირებას ავტომატური ტესტები მხოლოდ სინთეზურ
  სკანებზე აქვს და არა რეალურად დაბეჭდილ და დასკანერებულ გვერდებზე. ეს ეხება
  ყოველ ამონაბეჭდს, რომელიც უფრო მსხვილი წერტილებით ან დაცვით არის
  შექმნილი.
- ფურცლების ავტომატური მიწოდების სკანერები გამოცდილი არ არის, გარდა იმისა,
  რომ პროგრამამ სამ რეალურ სკანზე წერტილების ბადე იპოვა.
- ერთი ამონაბეჭდის სამი რეალური 300 dpi სკანის გაზომვამ დაახლოებით 286 dpi
  აჩვენა, რაც ნიშნავს, რომ ეს ამონაბეჭდი რეალური ზომის დაახლოებით 95%-ით
  დაიბეჭდა. უფრო პატარა წერტილების წაკითხვა უფრო ძნელია, ამიტომ დაბეჭდეთ
  რეალური ზომით (100%).
- ჭავლური პრინტერები გამოცდილი არ არის.

## იგივე გვერდები, რასაც C პროგრამა ქმნის { #the-same-pages-as-the-c-program }

Python კოდერის გვერდები ბაიტ-ბაიტ ემთხვევა თავდაპირველი C `optar`-ის შედეგს
A4-ისთვის, Letter-ისთვის და შეცდომების შესწორების ხუთივე რეჟიმისთვის. Python
დეკოდერის ჯვრების პოზიციები და აღებული ბიტები ბიტ-ბიტ ემთხვევა C
`unoptar`-ისას სინთეზურ სატესტო გამოსახულებებზე. ორივე შედარებულია C
პროგრამების შედეგებთან, რომლებიც ერთხელ ჩაიწერა და ინახება `tests/vectors`-ში.

თვითამოცნობადი ამონაბეჭდის (ანუ ამონაბეჭდის, რომლის გვერდებიც თავად
მიუთითებს, რომელ დოკუმენტს ეკუთვნის და რომელი გვერდია) ყოველი გვერდი მაინც
ჩვეულებრივი optar-ის გვერდია: იმავე ბადის ზომით აგებული C `unoptar` მის
წერტილებს ზუსტად კითხულობს (ჩაწერილია მსხვილი წერტილებისთვის A4-ზე და საშუალო
წერტილებისთვის Letter-ზე). ის აბრუნებს არა ფაილს, არამედ მონაცემებს, რომლებშიც
ფაილი დამატებით ცნობებსა და დაცვაშია შეფუთული.
