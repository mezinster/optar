# ბრძანების სტრიქონი { #command-line }

ბრძანება `optar` ფაილს გვერდებად კოდირებს და სკანებს ისევ ფაილად
დეკოდირებს. მას არ სჭირდება არც C კომპილატორი, არც libpng და არც
ImageMagick.

    optar encode INPUT [-o BASE] [--paper a4|letter] [--to pdf|png|pgm] [--label TEXT] [--no-tag]
                 [--dots standard|medium|big|large|xlarge] [--protect none|standard|high]
                 [--compatible] [--format STRING]
    optar decode BASE [-o OUTPUT] [--paper a4|letter] [--format STRING] [--debug-images] [--force]
                 [--no-slow-reader]
    optar --version

## encode { #encode }

`encode` ნაგულისხმევად წერს `BASE.pdf`-ს (`BASE`-ის ნაგულისხმევი მნიშვნელობაა
`optar_out`), ხოლო `--to`-ით — გვერდებს `BASE_0001.png` (ან `.pgm`),
`BASE_0002.png`, ...

| რას მიუთითებთ | რას მიიღებთ |
|---|---|
| არც `--dots`, არც `--protect`, ან `--compatible` | ამონაბეჭდს, რომელსაც 0.2.0 და C პროგრამა წაიკითხავს: სტანდარტული წერტილები, დაცვის გარეშე |
| მხოლოდ `--dots X` | ამ წერტილის ზომას სტანდარტული დაცვით |
| მხოლოდ `--protect LEVEL` | სტანდარტულ წერტილებს ამ დაცვით |
| `--protect none` | დაცვის გარეშე |

ბოლო სამიდან ნებისმიერი ქმნის თვითამოცნობად გვერდებს (გვერდებს, რომლებიც
თავად მიუთითებს, რომელ დოკუმენტს ეკუთვნის და რომელი გვერდია), რომელთა
წასაკითხადაც საჭიროა optar 0.3 ან უფრო ახალი. მაგალითად:

    optar encode photo.jpg -o photo --dots large --protect high

წერტილის ზომები და დაცვის დონეები აღწერილია განყოფილებაში
[„ფაილის ქაღალდზე ჩაწერა“](put-on-paper.md#dot-size).

თავსებადი ამონაბეჭდის ყოველ გვერდზე დაბეჭდილია
[ჭდე](identification.md#the-tag); მის გამოსატოვებლად დაამატეთ `--no-tag`.

`--paper`-ის ნაგულისხმევი მნიშვნელობაა A4.

## decode { #decode }

`decode` კითხულობს ფაილებს `BASE_0001.png`, `BASE_0002.png`, ... და მონაცემებს
წერს `-o OUTPUT`-ში ან stdout-ში. ის მხოლოდ ასეთი სახელების ფაილებს
კითხულობს.

რას აკეთებს, ამონაბეჭდზეა დამოკიდებული. გადაწყვეტილებას ის პირველი სამი
სკანით იღებს: თუ ვერცერთი მათგანი ვერ ამოიცნობა თვითამოცნობად გვერდად,
ნაკრებს 0.2.0 ან უფრო ადრეული ვერსიის ამონაბეჭდად მიიჩნევს.

### თვითამოცნობადი გვერდები { #self-identifying-pages }

`decode` თავად სკანებიდან არკვევს, რა არის ისინი.

- ის სკანებს იღებს ნებისმიერი თანმიმდევრობითა და ნებისმიერი ორიენტაციით.
- სკანი, რომლის წაკითხვაც ვერ ხერხდება, ითვლება გვერდად, რომელიც აკლია.
- სკანი, რომელსაც წაკითხვის ჩვეულებრივი მეთოდი ვერ ამოიცნობს, ჯერ
  [ნელ მეთოდს](slower-reader.md) გადაეცემა, თუ არ მიუთითებთ
  `--no-slow-reader`-ს.
- ის მონაცემებს ასწორებს, მათ ნამდვილ ზომამდე კვეცს და ანაბეჭდს ადარებს.
- ფაილს წერს მხოლოდ მაშინ, როცა ანაბეჭდი ემთხვევა; გამონაკლისია `--force`,
  რომელიც აღდგენილს ინახავს მაშინაც, როცა ფაილმა შემოწმება ვერ გაიარა.
  `--force`-ითაც კი არაფერი ინახება, თუ გვერდების ნახევარზე ნაკლებია
  წაკითხული.

### 0.2.0 ან უფრო ადრეული ვერსიის ამონაბეჭდები { #printouts-from-020-or-earlier }

- `--paper` უნდა იყოს იგივე, რაც კოდირებისას.
- გვერდი სწორად უნდა იდგეს (წიგნისებრი ორიენტაცია, წარწერა ქვემოთ).
  ალბომური ორიენტაციის სკანები აქ მხარდაჭერილი არ არის, რაც C დეკოდერიდან არის
  მემკვიდრეობით მიღებული. სამაგიდო აპლიკაცია ყველა ამონაბეჭდისთვის ნებისმიერ
  ორიენტაციას იღებს.
- `decode` შედეგს ჭდეში მითითებულ ზომამდე არ კვეცს და ანაბეჭდს არ ადარებს:
  შედეგი ყოველთვის ნულებით არის შევსებული მთელ გვერდამდე. სამაგიდო
  აპლიკაცია ორივეს აკეთებს. თუ თქვენი მონაცემებისთვის ეს მნიშვნელოვანია,
  შეფუთეთ ისინი tar-ით.
- `--force` არაფერს ცვლის და `decode` ამას გეტყვით.

## დასრულების კოდი { #exit-status }

| კოდი | მნიშვნელობა |
|---|---|
| 0 | წარმატება. თვითამოცნობადი გვერდებისთვის: ფაილმა შემოწმება გაიარა. |
| 1 | მონაცემები დეკოდირდა, მაგრამ შეუსწორებელია, ან გვერდების ნუმერაციაში გამოტოვებაა, ან (თვითამოცნობადი გვერდებისთვის) ფაილმა შემოწმება ვერ გაიარა. |
| 2 | გამოყენების ან შემავალი მონაცემების შეცდომა. |

## შეცდომების შემსწორებელი კოდი { #the-error-correcting-code }

ნაგულისხმევია გოლეის კოდი 24/12. ასევე მხარდაჭერილია 2-დან 5-მდე რიგის
ჰემინგის კოდები, რომლებიც `--format`-ით აირჩევა (ფორმატის სტრიქონის მეექვსე
ველი). ფორმატის სტრიქონი განსაზღვრულია [ფორმატის სპეციფიკაციაში](format.md).
