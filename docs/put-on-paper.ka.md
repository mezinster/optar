# ფაილის ქაღალდზე ჩაწერა { #put-a-file-on-paper }

## აპლიკაციაში { #in-the-application }

გახსენით ჩანართი „ქაღალდზე ჩაწერა“.

![ჩანართი „ქაღალდზე ჩაწერა“ არჩეული ფაილით](img/put-on-paper.png)

1. აირჩიეთ ფაილი ან გადმოიტანეთ ის ჩანართზე.
2. აირჩიეთ A4 ან US Letter.
3. აირჩიეთ [წერტილის ზომა](#dot-size) და [დაცვა](#protection). ფანჯარა
   იხსნება სტანდარტული წერტილებითა და სტანდარტული დაცვით.
4. მიეცით ფაილს სახელი. სტრიქონი „დაიბეჭდება:“ აჩვენებს ტექსტს, რომელიც
   ყოველ გვერდზე დაიბეჭდება.
5. წაიკითხეთ მის ქვემოთ მოცემული სტრიქონი: ის აჩვენებს, რამდენი გვერდი
   სჭირდება ფაილს და, დაცვის შემთხვევაში, ამ გვერდებიდან რამდენი შეიძლება
   დაიკარგოს.
6. „PDF-ის შექმნა…“ ინახავს PDF-ს.

თუ მონიშნავთ „თავსებადობა optar 0.2-თან და თავდაპირველ optar-თან“, შეიქმნება
ამონაბეჭდი, რომელსაც ეს ძველი პროგრამები წაიკითხავს. მას სტანდარტული
წერტილები აქვს და დაცვის გარეშეა.

ბრძანების სტრიქონიდან: იხ. [`optar encode`](command-line.md#encode).

## ბეჭდვა { #printing }

დაბეჭდეთ PDF რეალური ზომით (100%) და არა „გვერდზე მორგებით“, 600 dpi
გარჩევადობის ლაზერულ პრინტერზე. ჭავლური პრინტერები გამოცდილი არ არის.

ამონაბეჭდს, რომელიც რეალურ ზომაზე პატარა გამოდის, უფრო პატარა წერტილები
აქვს, რომელთა წაკითხვაც უფრო ძნელია. ერთი რეალური ამონაბეჭდის გაზომვამ
რეალური ზომის დაახლოებით 95% აჩვენა.

## წერტილის ზომა { #dot-size }

წერტილის ზომა განსაზღვრავს, რა ზომით იბეჭდება თითოეული მონაცემთა წერტილი.
უფრო მსხვილი წერტილები უფრო დაბალი გარჩევადობის სკანსაც უძლებს, მაგრამ
გვერდზე ისინი ნაკლები ეტევა, ამიტომ გვერდი ნაკლებ მონაცემს იტევს. მონაცემთა
წერტილი 600 dpi პრინტერის 3, 4, 5, 6 ან 9 წერტილის ტოლია.

ცხრილში მოცემულია სკანირების გარჩევადობა (სამი სკანის პიქსელი თითო მონაცემთა
წერტილზე) და ბაიტების რაოდენობა, რომელსაც ერთი გვერდი იტევს დაცვის
დამატებამდე:

| წერტილის ზომა | პარამეტრი | პრინტერის წერტილი თითო მონაცემთა წერტილზე | სკანირება | A4 გვერდი | Letter გვერდი |
|---|---|---|---|---|---|
| სტანდარტული | `standard` | 3 | 600 dpi | 199 773 | 192 591 |
| საშუალო | `medium` | 4 | 450 dpi | 114 904 | 110 463 |
| დიდი | `big` | 5 | 360 dpi | 73 027 | 69 463 |
| მსხვილი | `large` | 6 | 300 dpi | 49 119 | 48 403 |
| ძალიან მსხვილი | `xlarge` | 9 | 200 dpi | 21 606 | 21 127 |

აირჩიეთ წერტილის ზომა იმ სკანერის მიხედვით, რომელიც გვერდებს წაიკითხავს, —
შესაძლოა, მრავალი წლის შემდეგ. თუ არ იცით, უფრო მსხვილი წერტილები უფრო
უსაფრთხო არჩევანია.

## დაცვა { #protection }

დაზიანებისგან დაცვა არის დამატებითი მონაცემები, განაწილებული დოკუმენტის ყველა
გვერდზე, რომელთა საშუალებითაც პროგრამა ასწორებს დაზიანებულ ადგილებს და
აღადგენს დაკარგულ გვერდებს. არჩევანია: „არა“, „სტანდარტული“ და „მაღალი“.

- ის ქაღალდს მოითხოვს: სტანდარტული დაცვა გვერდების რაოდენობას დაახლოებით
  14%-ით ზრდის, მაღალი — დაახლოებით 34%-ით.
- დამატებითი მონაცემები ისეა განაწილებული, რომ ლაქა, მოგლეჯილი კუთხე თუ
  გვერდი, რომელიც აკლია, ფაილის ყოველ ნაწილს დაახლოებით ერთნაირ მცირე
  დანაკარგს აყენებს. სწორედ ამ მცირე დანაკარგს ასწორებს დაცვა.
- დაცვის შემთხვევაში გვერდების ნაწილი დაცვის მონაცემებს ატარებს, ყოველი
  გვერდი კი იმეორებს მოკლე ჩანაწერს, რომელიც მიუთითებს, რომელ დოკუმენტს
  ეკუთვნის და რომელი გვერდია. ამიტომ ფაილს ზემოთ მოცემულ ცხრილში ნაჩვენებზე
  ნაკლები ადგილი რჩება.

### მთელი გვერდის დაკარგვა { #losing-a-whole-page }

ფანჯარა და `optar encode` დაკარგული გვერდის აღდგენას გპირდებათ მხოლოდ
საკმარისად გრძელი დოკუმენტებისთვის და მაშინ წერს: „T გვერდიდან შეიძლება
დაიკარგოს N“.

| დაცვა | შეიძლება დაიკარგოს 1 გვერდი, თუ დოკუმენტი შეიცავს | შეიძლება დაიკარგოს 2 გვერდი, თუ დოკუმენტი შეიცავს |
|---|---|---|
| სტანდარტული | 12 ან მეტ გვერდს | 24 ან მეტ გვერდს |
| მაღალი | 6 ან მეტ გვერდს | 12 ან მეტ გვერდს |

ამაზე ნაკლები გვერდის შემთხვევაში გვერდების შიგნით დაზიანება სწორდება, მაგრამ
მთელი გვერდის დაკარგვისას ფაილი იკარგება. დაპირება შეგნებულად ფრთხილია და
დოკუმენტიდან შეიძლება იმაზე მეტი აღდგეს, ვიდრე დაპირებულია.

### ყველაზე დიდი ფაილი { #the-largest-file }

ფაილს, რომლის დაცვით შექმნილი ამონაბეჭდიც ქაღალდზე 256 MiB-ზე მეტი იქნებოდა,
პროგრამა არ იღებს. ამ შემთხვევაში ფანჯარა გეტყვით, დაეტეოდა თუ არა ფაილი
დაცვის გარეშე ან უფრო წვრილი წერტილებით.

## რომელ პროგრამებს შეუძლია ამონაბეჭდის წაკითხვა { #which-programs-can-read-the-printout }

| ამონაბეჭდი | ვინ წაიკითხავს |
|---|---|
| ნებისმიერი წერტილის ზომა, სტანდარტულის გარდა, ან ნებისმიერი დაცვა | optar 0.3 ან უფრო ახალი. წაკითხვისას არაფრის მითითება არ არის საჭირო. |
| სტანდარტული წერტილები, დაცვის გარეშე, მონიშნულია „თავსებადობა“ | ყველა ვერსია და თავდაპირველი C პროგრამა |

0.2.0 აპლიკაციას უფრო მსხვილი წერტილების გვერდების წაკითხვა საერთოდ არ
შეუძლია. სტანდარტული წერტილებითა და დაცვით შექმნილი გვერდებიდან 0.2.0 და
C პროგრამა აბრუნებს არა ფაილს, არამედ მონაცემებს, რომლებიც დამატებით
ცნობებსა და დაცვაშია შეფუთული.

მიზეზები აღწერილია განყოფილებაში
[„როგორ ამოიცნობა გვერდი“](identification.md).

!!! note "თავსებადი ამონაბეჭდიდან ფაილი ნულებით შევსებული ბრუნდება"
    0.2 და უფრო ძველი პროგრამებისთვის შექმნილი ამონაბეჭდი თავის მონაცემებში
    ფაილის სიგრძეს არ ინახავს; ის მხოლოდ წარწერის ჭდეშია. ბრძანების
    სტრიქონის `optar decode` და C პროგრამა ასეთ ფაილს აბრუნებს მთელ
    გვერდამდე ნულებით შევსებულს. თუ თქვენი მონაცემებისთვის ეს მნიშვნელოვანია,
    შეფუთეთ ისინი tar-ით.
