# optar 0.6.1 Fixes Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Fix the defects parked when 0.6.0 shipped, and apply the owner's three decisions, so that 0.6.1 can be tagged.

**Architecture:** Each task is a small, separately testable change. The catalogue-loading and language-choice rules stay in `optar.i18n`, called only from `cli.py` (library) and `optar_gui/text.py` (window). Layout fixes stay in the widgets. English output changes only where this plan says so (Task 4).

**Tech Stack:** Python 3.12+ (CI 3.15), PySide6, pytest/pytest-qt, PyInstaller, tomllib.

**Spec:** `docs/superpowers/specs/2026-11-19-multilingual-design.md` (binding; Tasks 2 and 3 amend it in the same commit). The findings come from `.superpowers/followups-0.6.1/` (a local folder, not in git): `final-review-report.md` (M2, M4, M6, M11), `final-fix-rereview.md` (F2, F3, F4, F7) and `multilingual-ledger.md` (x6).

**Owner decisions, 2026-11-20:**
1. Fix the case of the two English strings, `gui.reason.not_decodable` and `gui.repair.unprotected`. This deliberately changes English output.
2. Number grouping follows each language: no separator in four-digit numbers in `ru uk be pl es`; separators from five digits up. `en ka tr it` group from four digits, as now.
3. macOS has its own workflow (done in PR #16, not part of this plan).

## Global Constraints

- English output stays byte-for-byte as it is, except the two strings of Task 4.
- `str(e)` of library exceptions is unchanged.
- Only `cli.py` imports `optar.i18n` from the library. In the window, only `optar_gui/text.py` imports it, and it does so lazily: importing `text.py` loads neither numpy nor `optar`.
- `text.py`, `document.py` and `work.py` import no Qt. Nothing under `src/optar` imports Qt or `optar_gui`.
- A new or changed catalogue string goes into all nine catalogues in the same commit.
- `tests/vectors` and `lega-c/` are never edited. Tests write only under `tmp_path`.
- Commit subjects are capitalised, third-person present, with no prefix ("Fixes …", "Adds …").
- Heavy suites run one at a time on this machine: the default suite with `-n 6`, the gui suite with `-n 4`. Subagents run focused tests only.
- English pages under `docs/` are not changed by this plan; each English page change would make eight translations stale. Documentation follow-ups go to the separate documentation-only pull request.

## Review Focus

1. The saved window language's catalogue is malformed: the window must still open, in English, with a language menu listing the readable languages. Covered in Task 1.
2. A release build missing or breaking one catalogue: `optar-gui --self-test` must fail, not report "8 languages" and pass. Covered in Task 1.
3. `OPTAR_LANG=ru` together with `LC_ALL=C`: OPTAR_LANG wins, so the answer is `ru`; `C` only ends the search at its own place. Covered in Task 2.
4. Grouping of negative numbers and decimals: `-1234` and `1234.5` in Russian get no separator; `12345.5` does. Covered in Task 3.
5. At the window's minimum size, in Georgian or Turkish, with a long file name in the summary: every button is whole and inside its pane. Covered in Task 6.

Covers owner decision 2.

**Interfaces:**

- Produces: `_MIN_GROUPING: dict[str, int] = {"en": 1, "ru": 2, "uk": 2, "be": 2, "pl": 2, "ka": 1, "tr": 1, "it": 1, "es": 2}`. With minimum `m`, an integer part of `d` digits is grouped only when `d >= 3 + m`: `m = 1` groups from four digits, `m = 2` from five. The separators still come from each catalogue's `[format]` table. `number()` and `decimal()` apply the rule to the absolute value of the integer part, so the sign does not count as a digit. A code missing from the table uses English's 1.
